# HTTP Settings

The former custom response header example is now a foundational proxy plugin.
Its ID is `http-settings`, its implementation types are `HttpSettingsPlugin`,
`HttpSettingsOptions` and `HttpSettingsMiddleware` in `LyWaf.Plugins.Sys.HttpSettings`.
Existing `Headers` configuration remains compatible. Configurations using the former plugin ID must
rename their load, options, scoped overrides and enablement keys to `http-settings`.
Its implementation and bilingual resources
are owned by `Plugins/Sys/HttpSettings`, not the host.

## Execution

The plugin registers only at `PluginProxyStage.First`. Request operations run
before proxy middleware; the response callback runs after inner `OnStarting`
callbacks, including short-circuited cache hits, preflights and WAF responses.
The plugin manager gates it by lifecycle state, including activation after startup.
The administration port, unmatched requests outside the proxy pipeline, and
responses emitted before that pipeline (for example ACME challenges) are outside
its scope. No response body is buffered or modified.

CORS, compression, caching and HTTPS redirects keep their existing dedicated
implementations. This plugin supplies common header policy rather than a second
implementation of those features. Existing inner middleware can still modify
request headers after this plugin; response header overrides are final at
`OnStarting` within this pipeline.

## Configuration

Options inside the existing `Plugins:http-settings` block:

```yaml
Enabled: true
Headers:
  X-Frame-Options: SAMEORIGIN
RequestHeaders:
  X-Service: gateway
RequestHeadersIfMissing:
  X-Client-Type: browser
AppendRequestHeaders: {}
RemoveRequestHeaders:
  - X-Debug
ResponseHeaders:
  Cache-Control: no-store
AppendResponseHeaders:
  Vary: Accept-Language
RemoveResponseHeaders:
  - X-Powered-By
StatusCodes: []
SecurityHeaders: true
HstsMaxAgeSeconds: 0
RequestIdHeader: X-Request-ID
```

Enable the plugin through plugin management, or the repository's existing
`Plugins.Load`/enablement configuration. Setting request options `Enabled` alone
does not activate an unloaded or stopped plugin. The plugin remains disabled by
default; new security presets, HSTS and request IDs are opt-in.

The existing global/site/path configuration resolver is used per request.
As in other scoped plugins, dictionaries and lists replace the entire inherited
collection at that level; repeat any inherited entries you still need.
An explicit `Plugins.Load` list replaces automatic loading: retain every plugin
your deployment needs rather than copying this list unchanged into production.
For example, the following native configuration overrides HTTP policy only for
one site's `/api/**` routes:

```text
Plugins {
    Load = ["http-settings"]
    http-settings {
        SecurityHeaders = true
        RequestIdHeader = "X-Request-ID"
    }
}
Sites {
    example {
        Hosts = ["example.com"]
        Routes {
            api {
                Path = "/api/**"
                Plugins {
                    http-settings {
                        ResponseHeaders {
                            Cache-Control = "no-store"
                        }
                    }
                }
            }
        }
    }
}
```

This demonstrates plugin policy scopes only; it does not create an upstream or
replace proxy route configuration. Retain the actual site's listeners and routes.
The runnable configuration fragment is [example.ly](example.ly).

## Policy Semantics

Request ordering: fill absent values, set/overwrite, append, remove, then generate
the optional request ID. Response ordering: optional security defaults/HSTS,
legacy `Headers` defaults, set/overwrite, append, remove, then the request ID
(unless that response header is explicitly removed). Header names are compared
case-insensitively by the HTTP header dictionary.

- `Headers`: fills only absent response headers, preserving legacy behavior.
  Existing defaults remain `X-Powered-By: LyWaf` and
  `X-Frame-Options: SAMEORIGIN`. Explicit removal wins over these defaults.
- `ResponseHeaders`/`RequestHeaders`: replace existing values.
- `Append*`: append values; use deliberately for headers that permit multiples.
- `Remove*`: remove the named headers. Removing `Server` can remove an upstream
  value, but cannot disable a server header subsequently generated by Kestrel;
  that requires its host-level `AddServerHeader` setting.
- `StatusCodes`: applies to the complete response policy, not request mutations.
  Empty means every status including errors; supports exact codes, `20x`, `30x`,
  `4xx`, case-insensitive `x`, and `*`. Error responses are not excluded by default.
- `SecurityHeaders`: fills absent `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: SAMEORIGIN`, and
  `Referrer-Policy: strict-origin-when-cross-origin`. Explicit response settings
  can override/remove them. CSP and cross-origin isolation are application-specific
  and are not guessed automatically.
- `HstsMaxAgeSeconds`: 0 disables HSTS; a positive value adds an absent HSTS header
  only when the current request is HTTPS. No automatic `includeSubDomains` or
  `preload`. An existing HSTS header is retained unless explicitly overwritten.
- `RequestIdHeader`: empty disables it. Use an `X-` header or `Request-Id`.
  The server's trace identifier replaces untrusted inbound IDs and is echoed in
  the response, allowing correlation with request logs. It does not overwrite
  W3C `traceparent`. Explicit response removal suppresses the echo.

## Validation

Header names must be valid tokens, at most 128 characters. Values must be ASCII
printable text or horizontal tabs, at most 8192 characters. Each operation accepts
at most 128 names/values. Configuration validation rejects unsafe candidates;
the runtime policy also skips unsafe entries as defense in depth.

Framing, connection, encoding and routing identity headers are protected:
`Host`, `Content-Length`, `Content-Encoding`, `Content-Range`, `Transfer-Encoding`,
`Connection`, `Keep-Alive`, `Proxy-Connection`, `TE`, `Trailer`, `Upgrade`,
`HTTP2-Settings`, `Forwarded`, `X-Forwarded-For`, `X-Forwarded-Host`,
`X-Forwarded-Proto`, and `X-Real-IP`. Connection-nominated hop headers are also
skipped at runtime. This is not a mechanism for changing client identity or
altering bodies without updating framing.

References: [NGINX headers module](https://nginx.org/en/docs/http/ngx_http_headers_module.html)
and [Caddy header policies](https://caddyserver.com/docs/caddyfile/directives/header).
