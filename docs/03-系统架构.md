# 系统架构

## 架构分层

| 层 | 说明 | 关键组件 |
|----|------|----------|
| 配置层 | LY/YAML 配置解析与热更新 | LyConfig, LyToYaml, ConfigLoader |
| 服务层 | 后台服务与业务逻辑 | WAF、统计、认证、证书等模块 |
| 中间件层 | HTTP 请求/响应管线 | 核心与插件中间件 |
| 控制面 | REST API 与 Web 控制台 | ControlApi, JWT Auth |
| 数据层 | 持久化与分析 | DuckDB, SharedData |
| 插件层 | 可扩展框架 | ILyWafPlugin, PluginManager |

## 启动流程

`Program.cs` 作为组合根完成以下步骤：

1. 解析 CLI 参数（CommandLineParser）
2. 初始化 NLog 日志
3. 创建 WebApplicationBuilder
4. 加载配置（LY 格式或 YAML，应用负载均衡补丁）
5. 注册核心服务和插件服务到 DI 容器
6. 配置 Kestrel（多端口、TLS SNI、自定义 DNS）
7. 构建 WebApplication
8. 初始化子系统（插件、认证、WAF 规则、DuckDB 恢复）
9. 注册 API 端点（ControlApi）
10. 按顺序配置控制端和代理端中间件管线
11. 添加 YARP 反向代理（transforms + 健康检查）
12. 注册关闭处理器，启动应用

## 控制面与数据面

数据面处理业务请求，目标是低延迟、有界资源和故障旁路；控制面处理配置、查询和管理操作，允许更复杂的模型验证和数据库查询。插件统一 API 只进入控制面，代理中间件只进入数据面。

控制面变更通过配置、补丁或共享服务影响数据面。需要重建 Kestrel 监听、DI 注册或中间件结构的变更必须重启；普通规则和 Options 可按各模块能力热更新。

多节点部署中，版本化静态配置由配置分发服务负责，短生命周期安全状态由 `IRuntimeStateStore` 负责。状态先在本机同步生效，磁盘持久化和节点复制通过有界后台队列完成，数据面不会同步等待远程存储。合并规则和故障边界见[分布式运行状态](36-分布式运行状态.md)。

## 关键边界

- `Config/` 负责解析与映射，不应执行请求业务。
- `Services/` 持有状态和 I/O，中间件只做编排。
- `Middleware/` 必须保持短路径和可取消。
- `Control/` 负责认证后的管理 API，不承载插件业务路由。
- `Plugins/` 通过稳定契约扩展，不直接修改核心内部状态。
- `Frontend/` 不自行推导安全结果，以后端状态为准。

## 架构验证

排查启动问题时按“配置解析 -> DI 构建 -> 插件初始化 -> 端点映射 -> 管线构建 -> `app.Run`”定位。排查业务请求时按“监听 -> 路由 -> 高优先级插件 -> 核心防护 -> 低优先级插件 -> 上游”定位，避免只查看最终 502。
