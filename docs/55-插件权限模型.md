# 插件权限模型

插件通过 `PluginMetadata.RequestedPermissions` 声明 `Network`、`DataDirectory`、`ConsoleApi` 和 `SensitiveConfiguration`。外部插件只有在宿主 `Plugins:Permissions:<plugin-id>` 授予全部所需能力后才会启用；统一控制台 API 在每次分派前还会检查 `ConsoleApi`。系统插件由宿主信任并授予现有能力。

```json
{
  "Plugins": {
    "Permissions": {
      "example-plugin": "Network, DataDirectory, ConsoleApi"
    }
  }
}
```

`DataDirectory` 表示插件应只使用 `IPluginContext.DataDirectory`。宿主会创建该专属目录，但同进程 .NET 代码仍可直接调用文件和网络 API，因此该模型提供能力声明、启用门禁和审计边界，不构成操作系统沙箱。来自不可信发布者的插件必须在独立低权限进程或容器运行。

插件代理 API 已有请求体、速率和并发上限；生命周期操作及异常会进入日志、审计和统一指标。后续进程隔离实现之前，不应向同进程插件授予其不需要的权限，也不应把敏感配置注入普通插件服务。

`Plugins:LifecycleTimeoutSeconds` 默认是 30 秒，适用于初始化、启动、停止和重载。超时按生命周期失败记录，避免插件阻塞宿主。插件文件应通过 `IPluginStorage` 的流式句柄访问，路径会经过规范化并拒绝绝对路径和 `..` 越界；外部 HTTP 客户端应由 `IPluginContext.Network` 创建。
