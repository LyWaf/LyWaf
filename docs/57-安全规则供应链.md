# 安全规则供应链

LyWaf 的规则包不是可直接覆盖配置的普通 JSON。安装时必须依次通过大小限制、规则摘要、宿主版本范围和 RSA-PSS 发布签名校验，验证失败的文件不会进入运行时快照。

## 包格式

包包含 `packageId`、`version`、`minHostVersion`、可选的 `maxHostVersion`、`publishedAt`、`keyId`、`rulesSha256`、`signature` 和 `rules`。每条规则可附带 CVE 编号、命中解释和参考资料。

`rulesSha256` 是 `rules` 的 SHA-256。签名算法为 RSA-PSS/SHA-256，签名原文按行拼接：

```text
packageId
version
minHostVersion
maxHostVersion
publishedAt（UTC O 格式）
keyId
rulesSha256（小写）
```

发布者应先计算规则摘要，再对上述内容签名。公钥通过 `Protect.RulePackages.TrustedPublicKeys` 配置，私钥不得部署到网关。

## 发布流程

1. `POST /api/rule-packages/install` 以请求体上传离线 JSON 包。
2. `POST /api/rule-packages/download` 传入 `{ "url": "https://..." }` 在线下载；响应头和流式读取都受大小及超时限制。
3. `POST /api/rule-packages/{version}/activate` 传入 `canaryPercentage`。`0` 或 `100` 切换稳定版，`1..99` 按客户端 IP、域名和路径的稳定哈希灰度。
4. `POST /api/rule-packages/rollback` 回到上一稳定版。

激活只更新原子状态文件。请求线程读取已验签的内存快照，不在流量路径下载或解析规则包。`GET /api/rule-packages/{version}/rules/{ruleId}` 返回 CVE 和命中解释，`POST /api/rule-packages/feedback` 记录误报反馈。

这些接口由 `Control/Endpoints/RulePackageEndpoints.cs` 独立注册，不在 `ControlApi` 中实现业务逻辑。所有安装、激活、回滚和反馈操作都会进入控制台审计日志。

## 故障语义

下载、摘要、签名或兼容性校验失败时保持当前稳定版。重启只加载能够再次通过验签的落盘包；状态指向不存在或失效版本时以空规则包启动，不使用未验证内容。
