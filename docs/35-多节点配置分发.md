# 多节点配置分发

LyWaf 使用面向配置事务的最小协议，不照搬完整 xDS。控制节点负责选择版本、目标和批次；目标节点负责本地解析、校验、原子应用和回滚。

## 两阶段流程

1. Controller 从 `ConfigVersionService` 读取不可变版本内容和 SHA-256。
2. Controller 向当前批次所有节点发送签名 `prepare`。
3. Node 校验摘要并调用与本地修改相同的配置解析器，但不修改运行配置。
4. 当前批次全部 ACK 后，Controller 才发送 `commit`。
5. Node 创建本地配置版本、原子写入并执行路由和安全策略冒烟检查。
6. 任一 commit NACK 时，Controller 对本批次已提交节点发送补偿 `rollback`。

节点重复收到相同 prepare、commit 或 rollback 时返回幂等 ACK，不重复创建配置版本。进程重启后会读取 `node-state.json` 恢复最近任务和回滚指针。

## 灰度和暂停

创建任务可指定 `CanaryCount`、`BatchSize` 和 `PauseAfterEachBatch`。第一个批次使用 canary 数量；后续使用普通批次大小。暂停在正在执行的批次结束后生效，不会把同一批次停在 prepare 与 commit 之间。

任务状态包括 `Running`、`Pausing`、`Paused`、`Completed`、`Failed`、`RollingBack`、`RolledBack` 和 `RollbackFailed`。控制节点重启时把未完成的 Running 任务恢复为 Paused，必须人工确认后继续。

## 节点认证

机器接口位于 `/api/v1/distribution/agent/*`，不使用控制台 JWT。每个请求包含 Unix 时间、128 位随机 nonce 和 HMAC-SHA256 签名，签名覆盖操作名、时间、nonce 和正文摘要。节点校验时钟窗口并拒绝 nonce 重放。

HMAC 只验证身份和完整性，不提供机密性。生产环境必须使用 HTTPS，并用防火墙限制控制端口来源。全局 `SharedSecret` 可被节点级 `Secret` 覆盖，以便逐节点轮换。
签名 canonical string 固定用 LF（`\n`）连接字段，不随 Windows 或 Linux 本地换行格式变化。

## 配置

```ly
Distribution {
    Enabled = true
    Role = "Controller"
    NodeId = "control-01"
    SharedSecret = "${DISTRIBUTION_SECRET}"
    StateDirectory = ".lywaf-distribution"
    MaxConfigBytes = 4194304
    RequestTimeoutSeconds = 15
    AllowedClockSkewSeconds = 60
    Nodes {
        edge-01 { Endpoint = "https://10.0.0.11:7030" Tags = ["canary"] }
        edge-02 { Endpoint = "https://10.0.0.12:7030" }
    }
    Permissions {
        GlobalOperators = ["admin"]
        NodeOperators {
            edge-01 = ["east-operator"]
            edge-02 = ["east-operator"]
        }
    }
}
```

目标节点使用相同密钥并设置 `Role = "Node"`。Standalone 或未启用实例拒绝机器分发请求。

`GlobalOperators` 中的用户可操作全部节点；`NodeOperators` 只授予指定节点权限。两项都为空时沿用单管理员兼容行为，任何已登录控制台用户均可操作。生产环境应明确配置权限，避免新增控制台账号后自动获得分发能力。

## 管理 API

- `GET /api/v1/distribution/nodes`：主动读取节点版本、配置版本、状态和节点时间。
- `GET /api/v1/distribution/dashboard`：并行聚合节点在线状态、上游健康、安全事件和当前用户权限。
- `GET /api/v1/distribution/deployments`：查看任务与逐节点 ACK/NACK。
- `POST /api/v1/distribution/deployments`：从本机配置历史创建任务。
- `POST /api/v1/distribution/deployments/{id}/pause`：请求批次边界暂停。
- `POST /api/v1/distribution/deployments/{id}/resume`：继续下一批。
- `POST /api/v1/distribution/deployments/{id}/rollback`：回滚所有已 ACK 节点。

这些控制 API 使用控制台 JWT 并写审计日志；agent API 只接受节点 HMAC。

## 故障语义

- prepare NACK：整个批次不提交，节点继续使用旧配置。
- 网络超时：记作该节点 NACK，不推断请求是否执行；重试依赖节点幂等。
- commit 部分失败：回滚当前批次已提交节点，任务进入 Failed。
- 回滚失败：保留逐节点 `RollbackNack`，任务进入 `RollbackFailed`，等待运维处理。
- 网络分区：已完成批次保持新版本，未开始批次保持旧版本；恢复后从 Paused/Failed 状态人工确认。
- 时钟偏差：超过 `AllowedClockSkewSeconds` 的机器请求被拒绝，节点状态时间可用于定位偏差。

状态文件和候选内容位于 `StateDirectory`，不得提交版本控制。配置内容可能含敏感值，磁盘权限和传输 TLS 都必须按密钥材料处理。
