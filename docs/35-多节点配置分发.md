# 多节点配置分发

LyWaf 使用面向配置事务的最小协议，不照搬完整 xDS。控制节点负责选择版本、目标和批次；目标节点负责本地解析、校验、原子应用和回滚。

## 两阶段流程

1. Controller 从 `ConfigVersionService` 读取不可变版本内容和 SHA-256。
2. Controller 向当前批次所有节点发送签名 `prepare`。
3. Node 校验摘要并调用与本地修改相同的配置解析器，但不修改运行配置。
4. 当前批次全部 ACK 后，Controller 才发送 `commit`。
5. Node 创建本地配置版本、原子写入并执行路由和安全策略冒烟检查。
6. 任一 commit NACK 时，Controller 对本批次已提交节点发送补偿 `rollback`。

节点重复收到相同 prepare、commit 或 rollback 时返回幂等 ACK，不重复创建配置版本。进程重启后会读取 `node-state.json` 恢复最近任务和回滚指针。

prepare首先校验正文摘要，并拒绝同一任务ID使用不同正文或版本。节点只允许一个当前Prepared任务；已回滚或已被新任务替代的历史任务不能再次提交。prepare记录当前配置文件摘要，commit前再次核对，并在ConfigVersionService写入锁内执行最终摘要检查；同一服务内竞争写入时旧基准不能覆盖新配置，拒绝时不创建归档。外部进程直接修改文件不受该进程内锁保护，仍需避免绕过配置管理并发写入。尚未提交的任务可通过rollback撤销候选，不改动活动配置。升级前遗留且没有基准摘要的Prepared任务需要撤销后重新创建。

v2 Inbox核对未知commit时，支持恢复“配置及版本索引已写入、节点任务仍为Prepared”的中断状态：候选身份与摘要、最新目标版本的distribution任务标记、归档内容和当前文件必须全部匹配，再重新加载并校验配置后保存Applied及回滚版本。当前文件被修改或版本索引尚未落盘时不会推断提交成功。该测试通过构造中断后的磁盘状态验证，不等同于真实进程强杀覆盖所有写入边界。

## 灰度和暂停

创建任务可指定 `CanaryCount`、`BatchSize` 和 `PauseAfterEachBatch`。第一个批次使用 canary 数量；后续使用普通批次大小。暂停在正在执行的批次结束后生效，不会把同一批次停在 prepare 与 commit 之间。

任务状态包括 `Running`、`Pausing`、`Paused`、`Completed`、`Failed`、`RollingBack`、`RolledBack` 和 `RollbackFailed`。控制节点重启时把 Running/Pausing 恢复为 Paused，把中断的 RollingBack 恢复为 RollbackFailed，保留逐节点状态，必须人工核对后继续或重试回滚。兼容旧版带 UTF-8 BOM 的状态文件。新状态先写临时文件并 flush 到磁盘，再替换目标文件，成功后才更新内存；这不等同于对所有文件系统提供断电事务保证。

## 节点认证

机器接口位于 `/api/v1/distribution/agent/*`，不使用控制台 JWT。每个请求包含 Unix 时间、128 位随机 nonce 和 HMAC-SHA256 签名，签名覆盖操作名、时间、nonce 和正文摘要。节点校验时钟窗口并拒绝 nonce 重放。

HMAC 只验证身份和完整性，不提供机密性。生产环境必须使用 HTTPS，并用防火墙限制控制端口来源。全局 `SharedSecret` 可被节点级 `Secret` 覆盖，以便逐节点轮换。
签名 canonical string 固定用 LF（`\n`）连接字段，不随 Windows 或 Linux 本地换行格式变化。

## 配置

防重放记录保存在 `StateDirectory/replay`，先持久化再执行请求，重启后继续拒绝有效期内的重复nonce。当前保留601秒、最多10000条有效记录，覆盖最大300秒双向时钟偏差。目录不可写、记录损坏或占用冲突时拒绝请求；不能在运行期间清空该目录或放在不提供可靠文件锁的网络共享上。该实现优先保障安全，节点高频状态同步的批量化和认证吞吐仍需专项压测。

```ly
Distribution {
    Enabled = true
    Role = "Controller"
    NodeId = "control-01"
    SharedSecret = "${DISTRIBUTION_SECRET}"
    StateDirectory = ".lywaf-distribution"
    MaxConfigBytes = 4194304
    RequestTimeoutSeconds = 15
    AllowedClockSkewSeconds = 60
    Nodes {
        edge-01 { Endpoint = "https://10.0.0.11:7030" Tags = ["canary"] }
        edge-02 { Endpoint = "https://10.0.0.12:7030" }
    }
    Permissions {
        GlobalOperators = ["admin"]
        NodeOperators {
            edge-01 = ["east-operator"]
            edge-02 = ["east-operator"]
        }
    }
}
```

目标节点使用相同密钥并设置 `Role = "Node"`。Standalone 或未启用实例拒绝机器分发请求。

`GlobalOperators` 中的用户可操作全部节点；`NodeOperators` 只授予指定节点权限。两项都为空时沿用单管理员兼容行为，任何已登录控制台用户均可操作。生产环境应明确配置权限，避免新增控制台账号后自动获得分发能力。

## 管理 API

- `GET /api/v1/distribution/nodes`：主动读取节点版本、配置版本、状态和节点时间。
- `GET /api/v1/distribution/dashboard`：读取后台采集缓存，聚合节点在线状态、上游健康、安全事件和当前用户权限，不在页面请求中访问远端。控制器启动后主动采集，每轮最多并发8个节点，周期10秒（前一轮未结束时不重叠）。首次观测前标记等待，失败时保留最后成功快照并标记离线；最后成功观测超过60秒不再显示在线。响应NodeId必须与配置目标一致。节点很多或持续慢响应时，轮询周期可能超过10秒；这不是严格心跳实时保证。
- `GET /api/v1/distribution/deployments`：查看任务与逐节点 ACK/NACK。
- `POST /api/v1/distribution/deployments`：从本机配置历史创建任务。
- `POST /api/v1/distribution/deployments/{id}/pause`：请求批次边界暂停。
- `POST /api/v1/distribution/deployments/{id}/resume`：继续下一批。
- `POST /api/v1/distribution/deployments/{id}/rollback`：回滚已提交、已准备或结果未知的节点，并重试此前回滚失败的节点；已经成功回滚的节点不重复发送。

这些控制 API 使用控制台 JWT 并写审计日志；agent API 只接受节点 HMAC。

## 故障语义

### 独立攻击 IP 汇总

节点快照在同一统计锁内取得计数与完整攻击 IP 集合，集合最多4096项；超过上限时不传部分集合。控制器对完整集合取并集，不再相加各节点的独立 IP 数。旧节点未提供集合、集合数量与计数不一致、任一启用节点离线时，全局 `security.uniqueAttackIps` 返回 `null`，界面显示 `-`。普通累计事件计数仍仅汇总在线节点。

该值是各节点当前保留统计周期的并集，并非统一时间窗口；节点重置时间可能不同。大规模基数估算及统一窗口仍待实现。IP 集合属于敏感观测数据，仅通过已认证节点接口传输，生产环境必须启用 TLS。

汇总响应的 `coverage` 提供启用节点数、参与节点数、缺失节点及最早快照时间。`complete` 只表示全部启用节点参与，不表示统计窗口一致；无节点时为 false。页面用中英文显示完整或部分覆盖。节点新增 `statisticsStartedAt`，旧节点为 null；`statisticsPeriodsKnown` 仅表示参与节点均提供该字段，不代表各节点起始时间相同。离线缓存仅供节点详情参考，不计入当前汇总。

- prepare NACK：整个批次不提交，节点继续使用旧配置。
- prepare响应丢失：节点标记Unknown并暂停；人工继续时重新prepare确认内容，不推断为失败。
- commit响应丢失：先查询节点状态，确认同一任务Applied才继续；否则Unknown并暂停，不盲目回滚。
- 确认关联：客户端对 ACK/NACK 均检查 NodeId、DeploymentId 和 Stage，必须与请求精确匹配。错节点、旧部署或错误阶段的 HTTP 200 响应不构成确认，按协议异常进入结果核对流程。该检查同时适用于 v1/v2；响应真实性仍依赖生产环境 TLS。
- 暂停后恢复：同一批次已确认 `Ack` 的节点不重复发送 prepare/commit；未确认节点重新核对。已确认节点仍保留在当前批次的补偿集合中，后续节点拒绝时会参与回滚。
- commit明确NACK：补偿当前批次已准备节点（已提交则回滚，尚未提交则撤销候选），全部补偿成功后任务进入Failed。
- 回滚失败：明确拒绝保留逐节点 `RollbackNack`；传输异常保留 `Unknown` 和 `PendingStage=rollback`，允许后台查询确认。任务进入 `RollbackFailed`，不把网络异常误报为节点已拒绝。
- 发送前持久化：prepare、commit、手动与补偿rollback均先写入目标 `Unknown` 和对应 `PendingStage`，再调用网络。进程强杀时即使异常处理没有运行，后台仍可把恢复结果关联到原阶段。确认回填不自动推进批次。
- 手动回滚：覆盖 `Ack`、`Prepared`、`Preparing`、`Unknown` 和 `RollbackNack`，只有这些节点均确认回滚成功才显示 `RolledBack`。无法联系的节点不视为回滚成功。
- 网络分区：已完成批次保持新版本，未开始批次保持旧版本；恢复后从 `Paused` 状态人工确认。
- `Failed`、`RollbackFailed` 不允许继续提交；应先完成必要的回滚，再创建新任务。新任务使用新的任务标识，避免重用节点已处理的历史命令。
- `resume` 仅接受 `Paused`；`pause` 仅接受 Running/Pausing/Paused，不能通过暂停把终态或回滚中的任务改为可继续状态。
- 时钟偏差：超过 `AllowedClockSkewSeconds` 的机器请求被拒绝，节点状态时间可用于定位偏差。

状态文件和候选内容位于 `StateDirectory`，不得提交版本控制。配置内容可能含敏感值，磁盘权限和传输 TLS 都必须按密钥材料处理。

v2 命令 Inbox 读取已持久化结果时，损坏 JSON、缺失或非法摘要、超过1 MiB的记录返回 `node_inbox_corrupt`（503）；读取时发生 I/O 或权限错误返回 `node_inbox_unavailable`（503）。这两种情况均不重新执行命令、不覆盖原记录。应先修复存储问题并核对节点实际状态，不能直接删除记录后重试，否则可能重复执行已生效的命令。请求取消不转成记录损坏错误。
