# 分布式运行状态

## 解决的问题

配置分发只能保证节点拥有相同规则，不能保证运行中的临时状态一致。典型问题包括：节点 A 封禁 IP 后，请求切换到节点 B；验证码在节点 A 生成，却提交到节点 B；同一个插件任务因重试在多个节点重复执行。

LyWaf 的运行状态层采用“本地立即生效、流式持久化、有界异步复制、周期性反熵”的方式。请求热路径不等待远程节点，因此某个节点或网络故障不会拖垮代理请求。`RuntimeState.Enabled = false` 时仍保留本地状态和持久化能力，单机不依赖 Redis、数据库或消息系统。

## 状态语义

| 状态 | 域 | 合并方式 | 说明 |
| --- | --- | --- | --- |
| 动态白名单/黑名单 | `access.*` | LWW + 删除墓碑 | 每个 IP/CIDR 独立成键，避免整表覆盖 |
| 临时 IP 封禁 | `ip.blocked` | LWW + TTL | WAF 判定会读取本地缓存或复制状态 |
| 验证码待处理与挑战 | `captcha.*` | LWW + TTL | 挑战在本机原子消费，删除会传播 |
| CC 时间窗口 | `cc.access/attack/error` | G-Counter 分量合并 | 每节点分量取最大值，再求全局总数 |
| CC 处罚期 | `cc.triggered` | LWW + TTL | 切换节点后继续执行相同处罚 |
| 防篡改事件 | `web-tamper.event` | 每资源 LWW | 检测、自动恢复和接受基线都会同步 |
| 插件任务 | `plugin.task` | LWW + TTL | 记录 running/succeeded/failed |
| 插件幂等键 | `plugin.idempotency` | 本地原子占用 + 复制 | 正常网络下抑制重复执行 |

LWW 版本由 `(Sequence, NodeId)` 确定，序列相同时按节点 ID 稳定裁决。删除不是直接丢弃字典项，而是保留 24 小时墓碑，防止离线节点恢复后把旧值重新传播回来。

## 配置

```ly
RuntimeState {
    Enabled = true
    NodeId = "edge-01"
    StateDirectory = ".lywaf-runtime-state"
    QueueCapacity = 10000
    MaxValueBytes = 65536
    MaxJournalBytes = 134217728
    AllowedClockSkewSeconds = 60
    SharedSecret = "${RUNTIME_STATE_SECRET}"

    Peers {
        edge-02 { Endpoint = "https://10.0.0.12:7030" }
        edge-03 { Endpoint = "https://10.0.0.13:7030" Secret = "独立节点密钥" }
    }
}
```

每个节点的 `NodeId` 必须唯一且重启后保持不变。生产节点间接口应使用 HTTPS；共享密钥通过环境变量注入，不要提交到仓库。若使用节点独立密钥，发送端目标配置和接收端发送节点配置必须使用同一密钥。

## 数据与内存边界

状态先写入 `ConcurrentDictionary`，磁盘操作通过有界 Channel 在后台追加到 `runtime-state.jsonl`。恢复时使用 `FileStream` 和 `StreamReader` 逐行解析，不调用 `ReadAllText` 或把整个文件反序列化成集合。

- `MaxValueBytes` 限制单条正文，默认 64 KiB。
- `MaxJournalBytes` 限制启动时允许恢复的日志大小，默认 128 MiB。
- `QueueCapacity` 限制突发写入占用；队列满时记录丢弃数，请求线程不会等待磁盘。
- API 状态摘要不返回正文，避免泄露验证码答案、封禁原因或插件数据。

当前日志采用追加格式。长期运行环境应监控 `PersistedMutations`、`DroppedMutations` 和日志大小；后续可增加在线压缩快照，但压缩过程也必须使用临时文件原子替换。

## 复制协议

本地变更立即进入复制队列，后台向 `/api/runtime-state/agent/merge` 发送。每 30 秒重新广播仍有效的状态和墓碑，用于修复节点短暂离线造成的遗漏。远端合并后持久化但不会再次触发广播，避免请求环路。

机器接口使用 HMAC-SHA256，签名覆盖操作名、发送节点、时间戳、nonce 和请求体 SHA-256。接收端限制时钟偏差并拒绝 nonce 重放。该接口免 JWT，但仅此 agent 路径免除；以下诊断接口仍要求控制台认证：

- `GET /api/v1/runtime-state/status`
- `GET /api/v1/runtime-state/snapshots?domain=cc.triggered`

## 一致性和故障边界

这是可用性优先的最终一致设计。节点 A 刚写入到节点 B 收到之间存在短暂窗口；网络分区时各节点继续按本地状态处理，恢复后通过反熵收敛。

插件幂等占用无法在网络分区下提供严格全局唯一。涉及扣款、签发证书或不可重复外部操作的插件，必须使用拥有原子 `SET NX`/唯一索引/事务能力的中心存储，并把业务操作本身设计成幂等。LyWaf 的内置协调器适合抓取、刷新、分析等允许最终一致的后台任务。

## 外部后端评估

| 后端 | 适用场景 | 优点 | 代价与限制 |
| --- | --- | --- | --- |
| 内置 Peer | 中小规模边缘节点 | 无外部依赖，请求热路径可用 | 最终一致，节点数大时全互联成本高 |
| Redis | 严格幂等、共享验证码、短窗口计数 | TTL、原子命令、Lua/事务成熟 | 新增高可用组件；热路径依赖需熔断和本地降级 |
| PostgreSQL/MySQL | 防篡改确认、审计和任务状态 | 事务、唯一索引、查询能力强 | 不适合每请求同步写 CC 计数 |
| 消息系统 | 大规模事件传播与异步聚合 | 解耦生产消费、可重放 | 不能单独承担当前值查询或原子幂等 |

推荐演进方式是保留 `IRuntimeStateStore` 契约，按实际规模增加 Redis 状态后端；防篡改历史和审计可异步落数据库；消息系统只用于传播事件，不作为唯一状态真相。

## 插件使用

插件通过 `IPluginContext.Tasks` 使用统一任务协调器：

```csharp
if (!context.Tasks.TryStart("my-plugin", request.IdempotencyKey,
        TimeSpan.FromMinutes(10), out var task))
{
    return task;
}

try
{
    await RunImportAsync(cancellationToken);
    return context.Tasks.Complete("my-plugin", request.IdempotencyKey, true);
}
catch (Exception ex)
{
    context.Tasks.Complete("my-plugin", request.IdempotencyKey, false, ex.Message);
    throw;
}
```

幂等键应由稳定业务标识组成，不能使用每次请求新生成的 GUID，否则无法识别重复任务。

## 验证建议

1. 在两个节点配置不同 `NodeId`、相同密钥和互相的控制端地址。
2. 在节点 A 添加临时封禁，检查节点 B 的状态摘要与实际请求判定。
3. 停止节点 B，在 A 修改状态后重启 B，等待 30 秒反熵并确认收敛。
4. 重放完全相同的签名请求，应返回 `nonce 已使用`。
5. 停止全部节点后重启，确认未过期状态从 JSONL 流式恢复。
