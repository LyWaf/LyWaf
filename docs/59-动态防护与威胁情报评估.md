# 动态防护与威胁情报评估

本文记录两项安全能力的实施决策。评估结论是：当前不在 LyWaf 核心响应链实施 HTML/JavaScript 动态改写；威胁情报只允许通过签名规则包、IP 组或外部授权服务接入，不内置来源和授权不明的云端黑库。

## HTML/JavaScript 动态防护

动态注入脚本、变量混淆或页面加密会改变响应字节，破坏 ETag、SRI、CSP hash/nonce、流式 SSR、水合结果和边缘缓存键。它还会使源码映射与线上调试失真，并无法替代服务端输入验证。对 React/Vue 等框架，任意节点或脚本改写可能直接导致 hydration mismatch。

当前采用的替代方案是响应 WAF、网页防篡改基线以及站点自身配置 CSP/SRI。只有同时满足以下条件才重新评估动态改写：

1. 有明确且可量化的攻击模型，不以“隐藏源码”为安全收益。
2. 能在压缩前、缓存前确定执行顺序，并为改写后内容重新生成 ETag。
3. 能解析 CSP、nonce、SRI 和 HTML，而不是用正则替换页面。
4. 对流式响应、下载、大文件、非 HTML、SSR 水合和调试模式有明确旁路。
5. 建立主流框架兼容矩阵和回滚开关。

因此该项评估完成，结论为暂缓实施，不将网页防篡改描述为动态加密。

## 威胁情报

威胁情报源必须提供可审计授权、更新时间、撤销机制、误报申诉和离线快照。直接上传完整客户端 IP、URL、Cookie 或请求体到第三方会扩大隐私边界，默认禁止。

允许的接入方式：

- 离线或在线签名规则包：摘要、发布签名、兼容范围、灰度和回滚完整。
- IP 组：管理员导入获得合法授权的 CIDR/IP 集，规则更新失败保留最近有效版本。
- 外部授权：只发送白名单 Header 和有界 Body，配置超时、缓存及 fail-open/fail-closed。
- Anti-Bot JA4：只接受可信 TLS 终止层传入，不向外部服务自动上传指纹。

上线某一情报源前必须记录许可证、数据地区、保留期限、刷新频率、失效策略和紧急解除方式。来源不可验证、要求上传敏感流量或没有误封恢复接口时不得接入核心默认配置。
