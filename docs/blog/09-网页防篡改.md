# 网页防篡改：基线、目录规则与变更确认

> 专栏第 10 篇。目标是理解防篡改不是“发现变化就覆盖”，而是一套带人工确认的响应基线流程。

## 防篡改要解决什么

WAF 主要检查进入应用的请求。如果上游文件、发布产物或响应内容已经被替换，单纯的请求检测无法恢复可信页面。

网页防篡改插件保存已确认内容及指纹。上游发生变化时，它记录事件并继续向访客返回安全基线，管理员确认正常发布后才更新基线。

## 网站是第一层边界

插件按网站维护资源。配置路由中的具体域名会自动发现，也可以手工添加 `example.com` 或 `localhost:8080`。不要填写 `http://` 或 `https://`；检查时优先 HTTPS，失败后再尝试 HTTP。

同一 authority 不会因 scheme 不同建立两套数据。配置发现的网站也能修改备注。

## 精确路径与目录规则

```text
/index.html              精确资源
/*                       全站目录规则
/static/*                子目录规则
/static/{**match}        .NET catch-all 风格
/static/{**match**}      兼容写法
```

精确资源在添加时抓取。目录规则不会立即爬取整个站点，而是当真实请求经过 LyWaf 后，为匹配到的每个实际路径建立独立基线。

这种惰性收集避免一次性扫描海量 API，也保证只维护真实访问资源。

## 一分钟去重

请求命中后会尝试加入后台检查队列。同一资源一分钟内已经请求过，不会重复访问远程端；超过一分钟才允许再次后台检查。队列有容量，远程抓取有大小、超时和并发限制。

内容使用文件流和句柄处理，不将整个远程文件无界读入内存。这一点对大 JS、CSS 和异常响应很重要。

## 排除、暂停和删除

- 排除：目录规则仍存在，但指定实际路径不参与自动防护；仍可手动检查。
- 暂停：停用整个资源或规则。
- 删除子资源：移除基线，后续再次命中目录规则时会重新收集。
- 删除规则：删除规则及相关数据。

变化频繁、包含时间戳、个性化或随机数据的 API 应排除，不适合静态基线。

## 如何确认变更

检查结果提供 Git 风格差异：红色删除、绿色新增、双行号，未变化段可独立展开。还可以切换到本地安全基线和线上当前内容的完整版。

“继续使用安全基线”不信任这次变化；“确认正常，更新基线”将当前内容设为新基线。相同资源的待确认事件合并为最新一条，避免重复确认过期变化。

## 插件边界

页面、API 和中间件都属于 `web-tamper` 插件。控制台通过统一入口转发：

```text
/api/plugins/web-tamper/proxy/resources
```

核心控制台不应出现 `/api/web-tamper/...`，否则插件无法真正独立迁移和启停。

## 数据保护

基线和元数据位于输出目录的 `datas/web-tamper`。备份必须复制整个目录，不能只备份 JSON。全站 `/*` 可能产生大量实际路径，需要监控磁盘并持续排除动态接口。

## 完整演练

保护一个精确静态文件和一个目录规则，访问两个实际子路径，修改其中一个上游文件并执行检查。查看 Git Diff 风格差异、展开折叠内容、对比本地和线上全文，分别选择继续使用安全基线与接受新基线。

随后排除一个子资源并手动检查，确认排除只影响自动保护而不影响诊断；重启后验证资源、事件和基线仍存在。

## 完成标准

同一路径一分钟内远端最多拉取一次，大文件通过流和句柄处理，动态接口已排除，基线目录纳入备份和磁盘监控。
