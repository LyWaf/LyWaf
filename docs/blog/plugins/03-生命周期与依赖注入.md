# 生命周期、依赖注入与启停

## 生命周期职责

| 阶段 | 用途 | 不应执行 |
|---|---|---|
| `ConfigureServices` | 注册服务和 Options | 解析服务、启动任务 |
| `InitializeAsync` | 保存上下文、校验配置、准备轻量状态 | 长时间阻塞启动 |
| `ConfigureMiddleware` | 挂载控制端中间件 | 处理代理流量 |
| `ConfigureProxyPipeline` | 挂载业务代理中间件 | 创建后台死循环 |
| `StartAsync` | 启动订阅或受控后台任务 | 忽略取消令牌 |
| `StopAsync` | 停止任务、释放订阅和句柄 | 抛出未处理异常 |

```csharp
private MyPluginService? _service;
private IDisposable? _subscription;

public override Task InitializeAsync(IPluginContext context)
{
    base.InitializeAsync(context);
    _service = context.Services.GetRequiredService<MyPluginService>();
    _subscription = context.SubscribeEvent<RequestCompletedEvent>(OnRequestCompleted);
    return Task.CompletedTask;
}

public override Task StopAsync(CancellationToken cancellationToken)
{
    _subscription?.Dispose();
    return base.StopAsync(cancellationToken);
}
```

`IPluginContext` 还提供插件日志器、专属数据目录、配置、其他插件查询和事件发布能力。跨插件调用优先使用事件；确实需要强依赖时才使用 `Dependencies` 和 `GetPlugin`，并处理目标插件未启用的情况。

## 状态与异常

基类维护 `Unloaded -> Initialized -> Running -> Stopped`。初始化失败或启动失败必须记录明确日志，后台异常不应逃逸并终止宿主。`StopAsync` 应具备幂等性，因为配置变更、重载和应用退出都可能触发清理。

## DI 注册方式

无状态服务可注册单例；每次操作独立的轻量对象可以注册瞬时服务。插件中间件由宿主管线解析，其依赖必须在 `ConfigureServices` 阶段注册。

```csharp
public override void ConfigureServices(
    IServiceCollection services,
    IConfiguration configuration)
{
    base.ConfigureServices(services, configuration);
    services.AddSingleton<MyPluginState>();
    services.AddSingleton<MyPluginService>();
    services.AddHttpClient("my-plugin", client =>
    {
        client.Timeout = TimeSpan.FromSeconds(15);
    });
}
```

必须调用 `base.ConfigureServices`，否则 `DefaultOptions` 不会自动注册。避免在这里调用 `BuildServiceProvider`，那会产生第二套单例和难以释放的资源。

## 初始化与启动的区别

初始化适合解析服务、创建数据目录和验证静态配置；启动适合建立订阅、启动循环或恢复任务。初始化应当快速失败并给出具体配置错误。启动逻辑必须接受宿主传入的取消令牌，不能使用无法停止的 `Task.Run`。

## 幂等停止模板

```csharp
private CancellationTokenSource? _cts;
private Task? _worker;

public override Task StartAsync(CancellationToken cancellationToken)
{
    _cts = CancellationTokenSource.CreateLinkedTokenSource(cancellationToken);
    _worker = RunAsync(_cts.Token);
    return base.StartAsync(cancellationToken);
}

public override async Task StopAsync(CancellationToken cancellationToken)
{
    var cts = Interlocked.Exchange(ref _cts, null);
    cts?.Cancel();
    if (_worker is not null)
        await _worker.WaitAsync(cancellationToken);
    cts?.Dispose();
    await base.StopAsync(cancellationToken);
}
```

实际实现还应捕获正常取消产生的 `OperationCanceledException`。验证时连续执行启用、禁用、再次启用，并在每一步检查是否出现重复消费者或重复事件订阅。
