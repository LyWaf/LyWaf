# 把中间件嵌入代理管线

```csharp
public override void ConfigureProxyPipeline(IApplicationBuilder proxyApp)
{
    proxyApp.UseMiddleware<MyPluginMiddleware>();
}

public sealed class MyPluginMiddleware(RequestDelegate next, MyPluginService service)
{
    public async Task InvokeAsync(HttpContext context)
    {
        await service.ObserveAsync(context, context.RequestAborted);
        await next(context);
    }
}
```

中间件通过正常 DI 构造，不要从插件实例手工 `new`。如果要读取响应体，必须恢复原始 `Response.Body`，限制缓存大小，并在流式、压缩、升级连接和取消请求时正确退出。

## 优先级选择

- `Highest`、`High`：必须在核心防护前观察或阻断的安全功能。
- `Normal`：普通请求处理和业务扩展。
- `Low`、`Lowest`：统计、审计和非关键响应加工。

插件禁用后管线不会自动移除。中间件应查询可动态变化的服务状态并快速旁路：

```csharp
if (!service.Enabled)
{
    await next(context);
    return;
}
```

不要在请求线程同步访问远端。惰性采集应把路径放入有界 `Channel`，后台消费者按域名或资源做一分钟去重，再发起带超时的网络请求。

## 请求与响应处理边界

读取请求头和路由信息通常不需要缓冲。读取请求体时要考虑 `EnableBuffering`、大小限制和流位置恢复。读取响应体则需要临时替换输出流，风险和内存成本更高；除非功能确实依赖完整响应，否则优先使用状态码、头部或流式哈希。

```csharp
public async Task InvokeAsync(HttpContext context)
{
    if (!service.ShouldHandle(context.Request.Host, context.Request.Path))
    {
        await next(context);
        return;
    }

    service.TryEnqueue(new ObservedRequest(
        context.Request.Host.Value,
        context.Request.Path.Value ?? "/"));
    await next(context);
}
```

`TryEnqueue` 必须非阻塞。队列满时应记录采样指标并执行明确的丢弃策略，不能让业务请求等待后台采集。

## 异常策略

安全阻断插件可以在确定违规时终止管线；观察型插件发生内部异常时应记录后继续调用 `next`。无论哪种类型，都必须尊重 `RequestAborted`，不要将客户端取消误报成系统错误。

## 验证矩阵

至少覆盖普通 HTTP、HTTPS、非标准端口、大请求体、大响应、上游超时、客户端中断和 WebSocket/流式响应。记录中间件执行前后顺序，确认选择的优先级确实位于预期核心防护阶段。

禁用测试不能只看管理页状态：实际发送业务请求，确认中间件快速旁路；重新启用后若管线从未挂载，则应重启应用并在产品提示中说明。
