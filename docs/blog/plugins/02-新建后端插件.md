# 新建后端插件

内置插件放在 `Plugins` 下并随主项目编译。最小插件继承 `LyWafPluginBase`：

```csharp
using LyWaf.Plugins.Core;

namespace LyWaf.Plugins.MyPlugin;

public sealed class MyPlugin : LyWafPluginBase
{
    public override PluginMetadata Metadata => new()
    {
        Id = "my-plugin",
        Name = "示例插件",
        Version = "1.0.0",
        Description = "演示 LyWaf 插件完整接入",
        Author = "LyWaf",
        Priority = PluginPriority.Normal,
        EnabledByDefault = false,
        DefaultOptions = new MyPluginOptions()
    };

    public override void ConfigureServices(
        IServiceCollection services,
        IConfiguration configuration)
    {
        base.ConfigureServices(services, configuration);
        services.AddSingleton<MyPluginService>();
    }
}

public sealed class MyPluginOptions
{
    public bool Enabled { get; set; }
    public string HeaderName { get; set; } = "X-LyWaf-Plugin";
}
```

`Id` 是跨后端配置、API 和前端路由的稳定主键，发布后不要随意修改。设置 `DefaultOptions` 后，基类会注册对应的 Options 绑定，插件管理页也能识别该插件具有可配置项。

## 外部 DLL

外部插件项目需要引用与宿主一致版本的 LyWaf 插件契约，输出 DLL 放入 `PluginDirectory` 的任意子目录。主类必须是非抽象、可无参构造并实现 `ILyWafPlugin`。首次安装和程序集更新后重启应用，避免依赖版本及已构建管线不一致。

## 不要做的事

- 不要在构造函数访问 DI；发现阶段还没有最终服务容器。
- 不要使用与系统插件相同的 ID。
- 不要在 `ConfigureServices` 启动线程或打开文件。
- 不要把插件业务端点直接加进核心 `ControlApi`。

## 元数据字段说明

| 字段 | 建议 |
|---|---|
| `Id` | 全小写连字符，发布后保持稳定 |
| `Name` | 面向控制台用户的短名称 |
| `Version` | 使用语义化版本，程序集更新同步修改 |
| `Priority` | 只表达请求管线顺序，不表达插件重要程度 |
| `Dependencies` | 写插件 ID，不写类型名或程序集名 |
| `EnabledByDefault` | 外部或高风险插件建议为 `false` |
| `DefaultOptions` | 提供可绑定的公开配置对象 |

## 推荐文件拆分

插件类只做装配，不承载全部业务逻辑。状态和 I/O 放入服务，中间件只负责请求路径上的轻量调用：

```text
Plugins/MyPlugin/
├── MyPlugin.cs             # 元数据和装配
├── MyPluginOptions.cs      # 配置模型
├── MyPluginService.cs      # 状态、队列和业务逻辑
├── MyPluginMiddleware.cs   # 请求管线入口
└── Models/                 # API 请求与响应模型
```

这种拆分允许服务单独测试，也避免插件实例同时扮演 DI 容器、API 控制器和后台任务。

## 首次验证

1. 执行 `dotnet build`，确认插件类型被主项目编译。
2. 启动 LyWaf，检查发现日志是否包含 `my-plugin`。
3. 打开插件管理页，确认名称、版本、作者和默认启用状态正确。
4. 在 `config.ly` 中开启插件并重启，确认状态进入 `Running`。

若完全没有发现日志，先检查命名空间引用、类型是否抽象以及是否具备公开无参构造。若外部 DLL 加载失败，应同时检查其依赖 DLL 是否位于可解析位置。
