# config.ly 配置与插件数据目录

## 系统配置

```ly
Plugins {
    Enabled = true
    PluginDirectory = "plugins"
    DataDirectory = "plugin_data"
    EnableHotReload = false
    DisabledPlugins = ["my-plugin"]

    PluginConfigs {
        my-plugin {
            Enabled = true
            HeaderName = "X-LyWaf-Plugin"
        }
    }
}
```

启用状态优先级是 `Plugins:EnabledOverrides:{id}`，其次是插件配置中的 `Enable`/`Enabled`、`DisabledPlugins`，最后是系统插件默认值或 `EnabledByDefault`。后台切换通过补丁 `PluginEnabledStates` 映射到最高优先级的覆盖项。插件配置最终映射到 `Plugins:{pluginId}`；`context.GetPluginConfig<MyPluginOptions>()` 读取初始化上下文中的配置快照，使用 `IOptions<MyPluginOptions>` 或 `IOptionsMonitor<MyPluginOptions>` 时需要显式注册对应的配置绑定。整体说明见 [插件设计与管理指南](../../插件整体设计与管理指南.md)。

`PluginConfigs` 还可由运行时补丁加载，适合控制台修改。配置对象的公开属性应保持简单可序列化，敏感值不要通过默认配置元数据暴露给页面。

## 数据目录

`context.DataDirectory` 指向 `DataDirectory/{pluginId}`。数据库、基线、缓存和插件生成文件应写入这里，不要散落到程序根目录。

处理大文件时使用 `FileStream`、分块哈希和有上限的缓冲区，不要 `ReadAllBytes` 或把完整响应长期保存在内存。网络拉取应设置连接超时、总超时、最大响应大小和频率限制；临时文件采用写入后原子替换，异常路径必须关闭句柄。

## 配置绑定方式

构造服务时优先注入 `IOptionsMonitor<MyPluginOptions>`，这样配置补丁变化后可以读取最新值。只在初始化时需要快照时，可使用 `context.GetPluginConfig<MyPluginOptions>()`。

```csharp
public sealed class MyPluginService(IOptionsMonitor<MyPluginOptions> options)
{
    public bool Enabled => options.CurrentValue.Enabled;
    public string HeaderName => options.CurrentValue.HeaderName;
}
```

集合配置重新绑定时要注意追加语义。`LyWafPluginBase` 在初始化其 `DefaultOptions` 前会清空 List 和 Dictionary，但自行维护的配置对象仍需避免重复追加。

## 配置校验

配置模型应定义明确默认值，并在初始化时校验端口范围、绝对路径、时间间隔和容量上限。不要把无法解析的值悄悄替换成危险默认值。

```csharp
var options = context.GetPluginConfig<MyPluginOptions>();
if (string.IsNullOrWhiteSpace(options.HeaderName))
    throw new InvalidOperationException("HeaderName 不能为空");
```

## 数据布局建议

```text
plugin_data/my-plugin/
├── state.json
├── data.db
├── baselines/
├── cache/
└── temp/
```

持久数据与可再生成缓存应分目录。备份时优先保存数据库、配置和基线；清理操作只能删除 `cache`、`temp` 等明确目录，并在删除前验证解析后的绝对路径仍位于插件数据目录中。

## 验证方法

分别测试默认配置、`config.ly` 配置、控制台补丁和非法配置。重启后确认配置仍生效，并检查插件只在自己的数据目录写文件。大文件测试应观察进程内存保持有界。
