# 嵌入控制台页面

控制台在构建时自动扫描 `Frontend/src/plugins/*/plugin.ts`。新建目录：

```text
Frontend/src/plugins/my-plugin/
├── plugin.ts
├── api.ts
└── MyPluginPage.vue
```

`plugin.ts` 只负责声明路由：

```ts
import type { RouteRecordRaw } from 'vue-router'

export default {
  path: '/plugins/my-plugin',
  name: 'MyPlugin',
  component: () => import('./MyPluginPage.vue'),
  meta: { title: '示例插件' },
} satisfies RouteRecordRaw
```

页面通过 `api.ts` 调用统一插件 API，不直接依赖核心业务 API。页面状态、表单和类型留在插件目录；只有真正通用的组件才移入 `Frontend/src/components`。

## 页面管理原则

- 首屏必须处理加载、空数据、错误和插件禁用状态。
- 检查、同步等慢操作显示行级 loading，并显式处理超时。
- 危险操作二次确认，提交期间禁用重复点击。
- 页面刷新后路由可直接恢复，不依赖从管理页进入。
- 大列表分页或虚拟化；大内容按需、分块读取。

前端插件是编译期模块，并非从后端 DLL 动态下载的脚本。增加或修改页面后需要重新构建 `Frontend`。

## 最小页面结构

```vue
<script setup lang="ts">
import { onMounted, ref } from 'vue'
import { myPluginApi } from './api'

const loading = ref(false)
const error = ref('')
const status = ref<{ enabled: boolean } | null>(null)

async function load() {
  loading.value = true
  error.value = ''
  try {
    const { data } = await myPluginApi.status()
    status.value = data
  } catch {
    error.value = '加载插件状态失败'
  } finally {
    loading.value = false
  }
}

onMounted(load)
</script>
```

具体 Axios 返回结构应以仓库 `api` 实例为准。页面不要绕过统一封装自行拼接控制端地址，否则部署在反向代理子路径时容易失效。

## 页面状态分层

初次加载使用页面级 loading；单行检查、删除和保存使用行级状态，避免整个页面闪烁。插件未启用与网络失败要区分：前者给出启用入口或说明，后者允许重试。输入表单在服务端返回校验错误后保留用户内容。

## 路由与导航验证

1. 从插件管理页点击“管理”进入页面。
2. 在地址栏直接访问 `/plugins/my-plugin`。
3. 页面内刷新浏览器并检查服务器回退到前端入口。
4. 禁用插件后保留页面打开，确认 API 错误显示清晰。
5. 执行 `npm run build`，确认类型检查和动态导入均通过。

页面标题来自路由 `meta.title`。图标应使用项目已有图标库，不要依赖无法随构建发布的外部资源。
