# 后台任务与插件事件总线

## 事件总线

插件可订阅 `RequestStartedEvent`、`RequestCompletedEvent`、`ConfigurationChangedEvent` 和 `PluginStateChangedEvent`，也可发布自定义引用类型事件。

```csharp
private IDisposable? _subscription;

public override async Task InitializeAsync(IPluginContext context)
{
    await base.InitializeAsync(context);
    _subscription = context.SubscribeEvent<RequestCompletedEvent>(async e =>
    {
        await SaveSummaryAsync(e.StatusCode, e.Duration);
    });
}
```

事件处理器当前按订阅顺序等待执行，虽然单个处理器异常会被隔离，但慢处理器仍会拖慢发布者。处理器只做轻量判断和入队，实际 I/O 交给后台消费者；停止时释放 `IDisposable` 订阅。

## 有界后台队列

```csharp
private readonly Channel<string> _queue = Channel.CreateBounded<string>(
    new BoundedChannelOptions(1024) { FullMode = BoundedChannelFullMode.DropOldest });
```

请求中只用 `TryWrite` 投递。后台服务读取后按资源键记录最近拉取时间，一分钟内重复请求直接跳过，超过一分钟才访问远端。并发去重必须原子化，避免同一时刻多个请求同时穿透。

远端响应使用 `HttpCompletionOption.ResponseHeadersRead` 和流式复制，并限制最大字节数。本地内容用文件句柄分块哈希或比较，不把完整文件无条件读入内存。后台循环必须响应 `CancellationToken`，停止时完成 Channel、等待消费者并释放网络响应和文件流。

## 一分钟惰性拉取

惰性任务由真实前端请求触发，而不是定时扫描全部资源。请求到来时计算稳定键，例如标准化后的 `host:port + path`，再检查最近调度时间：

```csharp
if (!_lastScheduled.TryGetValue(key, out var last) ||
    now - last >= TimeSpan.FromMinutes(1))
{
    if (_lastScheduled.TryAdd(key, now) ||
        _lastScheduled.TryUpdate(key, now, last))
        _queue.Writer.TryWrite(item);
}
```

生产实现还要定期清理过期键，避免字典随路径数量无限增长。失败后是否立即允许重试应明确：通常仍保留短冷却时间，防止故障上游被请求风暴持续击打。

## 消费者模板

```csharp
await foreach (var item in _queue.Reader.ReadAllAsync(stoppingToken))
{
    try
    {
        await FetchStreamingAsync(item, stoppingToken);
    }
    catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
    {
        break;
    }
    catch (Exception ex)
    {
        logger.Warn(ex, "插件后台任务失败: {Key}", item.Key);
    }
}
```

消费者数量必须受控。对同一资源写文件或更新基线时使用每资源锁、事务或原子替换，避免并行结果相互覆盖。

## 可观测性与测试

记录入队、去重跳过、队列丢弃、成功、失败、超时和响应过大的计数，但不要为每个正常请求写高频 Info 日志。测试时并发请求同一路径，确认一分钟内只访问一次远端；再请求大量不同路径，确认队列和内存有明确上限。
