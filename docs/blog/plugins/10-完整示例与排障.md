# 完整全栈示例、测试与发布

一个完整插件至少完成以下闭环：

1. `MyPlugin` 声明元数据、DI、生命周期、代理中间件和管理入口。
2. `MyPluginService` 持有可变状态、数据访问和有界后台队列。
3. `MyPluginMiddleware` 在请求路径上快速匹配并投递任务。
4. `IPluginApiHandler` 暴露状态、配置和资源管理接口。
5. `Frontend/src/plugins/my-plugin/plugin.ts` 注册路由。
6. `api.ts` 只通过 `pluginProxyApi('my-plugin')` 访问后端。
7. 页面提供加载、超时、空状态、确认和错误反馈。

仓库中的 `Plugins/Sys/WebTamper/WebTamperPlugin.cs` 与 `Frontend/src/plugins/web-tamper` 是当前最完整的全栈参考：它同时使用代理中间件、后台服务、独立数据目录、统一 API、管理入口和插件页面。

## 验证清单

- 插件默认关闭、配置开启和管理页启停均符合预期。
- 直接刷新 `/plugins/my-plugin` 可正常加载。
- 浏览器网络面板中只有 `/api/plugins/my-plugin/proxy/*`，没有核心专用接口。
- 禁用后 API 返回不可用，任务停止，中间件快速旁路。
- 请求超时、取消、远端 5xx、大响应和磁盘不足不会拖垮代理。
- 重复请求受队列容量和频率窗口限制。
- 应用关闭后无残留任务、订阅、文件句柄或临时文件。

## 常见问题

**找不到插件**：确认 DLL 位于 `PluginDirectory`、类型可无参构造、依赖版本一致，且 ID 未与系统插件冲突。

**启用后中间件没有生效**：管线已在启动期构建，重启 LyWaf。运行时开关只适合已有中间件内部旁路。

**页面不存在**：确认 `plugin.ts` 默认导出路由，并重新构建前端。外部 DLL 不会自动携带 Vue 页面。

**插件 API 404**：确认实现 `IPluginApiHandler`，前端使用相同插件 ID，且请求发往控制端口。

**关闭后仍有工作**：检查 `StopAsync` 是否取消后台任务、释放事件订阅，并让中间件读取动态启用状态。

## 分阶段实现顺序

不要一次同时编写中间件、数据库和页面。推荐按以下顺序保持每一步可验证：

1. 只实现元数据，在插件管理页看到插件。
2. 加入 Options 和服务，验证配置绑定。
3. 实现只读 `status` API，用 curl 验证统一转发。
4. 注册前端路由和最小页面，显示状态。
5. 加入代理中间件，只记录匹配计数。
6. 加入有界队列、频率限制和持久化。
7. 最后补写操作 API、复杂页面和清理流程。

每一步都提交独立变更，出现问题时能够快速判断是发现、DI、管线、API 还是前端路由故障。

## 测试分层

服务层单元测试覆盖路径标准化、频率窗口、容量限制和配置校验。API 测试覆盖方法、状态码、非法 ID 和取消。集成测试启动测试宿主，确认插件优先级、启停和代理行为。前端至少执行构建，并用浏览器验证直接路由、慢请求 loading、超时和空状态。

性能测试应观察内存、句柄数、队列深度和上游请求次数，而不只是吞吐量。插件禁用后这些指标应停止增长。

## 发布包与升级

外部插件发布包应包含插件 DLL、非宿主共享依赖、默认配置说明、数据迁移说明和兼容的 LyWaf 版本。不要重复打包宿主已经加载的契约程序集，否则可能出现类型看似相同却无法转换的问题。

升级前备份插件数据目录。涉及数据库结构时使用可重复执行的版本迁移；启动失败应保留旧数据并给出恢复方法。程序集替换、代理管线变化和前端页面变化统一安排重启窗口。

## 完成标准

插件不是“页面能打开”就算完成。最终应满足：核心控制台没有插件专用业务路由，插件关闭不影响基础代理，后台资源有上限，数据可备份恢复，页面状态完整，并且日志足以定位发现、初始化、请求和停止阶段的问题。
