# 插件管理页、操作与页面入口

插件管理页展示元数据、状态、系统插件标识、配置入口、启停开关和插件自定义操作。后端通过 `GetActions()` 声明操作：

```csharp
public override IReadOnlyList<PluginAction> GetActions() =>
[
    new()
    {
        Id = "manage",
        Name = "管理",
        Type = "page-link",
        Path = "/plugins/my-plugin"
    },
    new()
    {
        Id = "clear-cache",
        Name = "清空缓存",
        Type = "button",
        Description = "删除插件生成的临时缓存"
    }
];
```

`page-link` 由管理页导航到插件路由；`button` 调用 `ExecuteActionAsync`；`log-viewer` 使用内置日志查看交互。一次性命令适合 Action，具有表格、表单或持续状态的功能应使用独立页面和统一插件 API。

```csharp
public override Task<PluginActionResult> ExecuteActionAsync(
    string actionId, Dictionary<string, string>? parameters)
{
    return actionId == "clear-cache"
        ? Task.FromResult(new PluginActionResult { Success = true, Message = "缓存已清理" })
        : base.ExecuteActionAsync(actionId, parameters);
}
```

管理页开关改变插件生命周期状态，但涉及代理中间件或程序集的变化仍建议提示用户重启。系统插件与普通插件的删除、覆盖权限也应区别展示。

## Action 类型选择

| 类型 | 使用场景 | 交互结果 |
|---|---|---|
| `page-link` | 配置、表格、持续状态 | 跳转插件页面 |
| `button` | 清缓存、重建索引等单次命令 | 显示成功或失败消息 |
| `log-viewer` | 插件日志查询 | 打开统一日志界面 |

Action ID 在插件内必须唯一。名称是用户界面文本，不能用于后端分派；修改显示名称不应破坏调用。

## 配置编辑入口

设置 `DefaultOptions` 后，管理页可识别 `hasOptions`。适合直接编辑的字段应具有安全默认值和简单类型。密码、私钥和 Token 不应把当前明文返回页面，可采用“已配置”状态和单独更新操作。

## 启停体验

切换期间禁用开关并显示 loading。失败时恢复原状态并展示后端消息。对于含中间件的插件，页面可以说明“配置已保存，重启后完整生效”，不要让用户误以为所有管线结构都已热更新。

系统插件的禁用会影响内建功能，应提供更强确认；外部插件重载涉及程序集卸载和依赖解析，也不应在有进行中任务时直接执行。

## 验证方法

逐一验证 Action 的显示、点击、防重复提交和错误反馈。刷新插件列表后状态应与后端一致；浏览器前进、后退和直接刷新插件页面都应正常。未知 Action ID 必须返回失败结果，而不是静默成功。
