# 把独立功能做成 LyWaf 插件

> 专栏第 11 篇。目标是开发一个最小插件，并明确哪些代码不应该留在核心控制台。

本文是快速导览。完整开发流程请继续阅读 [LyWaf 插件开发子专栏](plugins/README.md)，其中分别讲解后端创建、生命周期、配置、中间件、统一 API、控制台页面、后台任务与发布排障。

## 何时应该插件化

功能具有独立配置、页面、API、中间件或后台任务时，适合插件化。插件的核心价值不是目录分类，而是独立生命周期和清晰依赖边界。

## 最小后端插件

```csharp
public sealed class DemoPlugin : LyWafPluginBase
{
    public override PluginMetadata Metadata => new()
    {
        Id = "demo",
        Name = "Demo",
        Version = "1.0.0",
        Priority = PluginPriority.Normal,
        EnabledByDefault = false
    };

    public override void ConfigureServices(
        IServiceCollection services,
        IConfiguration configuration)
    {
        services.AddSingleton<DemoService>();
    }

    public override void ConfigureProxyPipeline(IApplicationBuilder proxyApp)
    {
        proxyApp.UseMiddleware<DemoMiddleware>();
    }
}
```

生命周期依次经过发现、服务注册、初始化、启动、请求处理和停止。安全拦截使用较高优先级，分析和普通改写不应无理由抢占 Highest。

## 统一插件 API

实现 `IPluginApiHandler`：

```csharp
public Task<IResult> HandleApiAsync(string path, HttpContext context)
{
    if (HttpMethods.IsGet(context.Request.Method) && path.Trim('/') == "status")
        return Task.FromResult(Results.Json(new { success = true }));
    return Task.FromResult(Results.NotFound());
}
```

访问路径为：

```text
/api/plugins/demo/proxy/status
```

不要在 `ControlApi.cs` 增加 `/api/demo/status`。统一入口保证认证、路由和插件启停边界一致。

## 前端页面

```text
Frontend/src/plugins/demo/
├── plugin.ts
├── api.ts
└── DemoPage.vue
```

`plugin.ts` 声明页面路由，`api.ts` 使用 `pluginProxyApi('demo')`。后端 `GetActions()` 返回 `page-link` 后，插件管理页可以显示管理入口。

## 插件数据安全

- 数据放入插件数据目录或明确的专用目录。
- 网络请求设置超时、大小和频率限制。
- 后台 Channel 设置容量并支持取消。
- 大文件使用流，不使用无界内存缓冲。
- 停止时释放事件订阅、任务、临时文件和句柄。

## 测试重点

启用、禁用、重启、超时、并发、大响应、磁盘不足和异常恢复都应测试。插件异常不能拖垮主代理，页面刷新后路由也必须可恢复。

## 读者实验

先创建只返回状态的 `my-plugin`，通过统一插件 API 调用，再注册 `/plugins/my-plugin` 页面和 `page-link`。最后加入一个只计数的代理中间件，验证禁用时旁路、重新启用及重启后的差异。

## 完成标准

核心 `ControlApi` 没有插件专用端点；插件 ID 在配置、API 和前端一致；后台资源有上限；停止时无残留任务和句柄；外部 DLL 与前端构建边界有明确发布说明。完整教程见 [插件子专栏](plugins/README.md)。
