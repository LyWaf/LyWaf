## 发布建议

- 建议每 2 至 4 天发布一篇，给读者留出实际操作时间。
- 每篇保留“上一期/下一期”，发布到平台后替换为真实文章链接。
- 命令默认以 PowerShell 展示，Linux 用户可去掉 Windows 特有换行符和 `curl.exe`。
- 示例域名使用 `example.com`，读者必须替换为自己的域名和上游地址。
- 截图可放在每篇的“验证”段落，不要使用包含真实密码、Token、IP 或私钥的图片。

## 文档与博客的区别

`docs/01` 至 `docs/23` 是按主题查阅的技术参考；本目录是按学习曲线编排的发布稿。博客正文尽量解释“为什么”，详细字段表则链接到参考文档，避免每篇重复整份配置手册。

## 单篇发布检查

- 标题和开头能够独立说明本篇目标。
- 配置、命令和代码均经过当前版本验证。
- 包含前置条件、操作步骤、验证、常见问题和小结。
- 上下篇链接及技术参考链接有效。
- 截图隐藏域名、IP、Token、Cookie、私钥和内部路径。
- 版本相关结论注明适用范围，避免使用易过期的文件数和行数。

## 配套实验环境

建议准备两个可识别实例 ID 的测试上游、一个测试域名、一个非标准端口站点和独立数据目录。所有安全阻断、目录规则和证书操作先在该环境验证，再迁移到生产。
