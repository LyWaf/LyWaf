# 从源码到首个代理站点

> 专栏第 2 篇。目标是在本机运行 LyWaf，并把请求转发到一个已有的 HTTP 服务。

## 准备环境

需要 .NET 9 SDK。重新构建控制台前端时还需要 Node.js 20 或更高版本。

```powershell
dotnet --info
node --version
git clone <repository-url> LyWaf
cd LyWaf
dotnet restore
dotnet build -c Release
```

如果只修改后端，仓库已有的 `control_html` 可以直接使用。前端发生变化时执行：

```powershell
cd Frontend
npm install
npm run build
cd ..
```

## 准备上游服务

假设业务服务监听 `127.0.0.1:8080`。先绕过 LyWaf 验证它：

```powershell
curl.exe -i http://127.0.0.1:8080/
```

如果这里失败，先修复业务服务。否则后续的 502 很难判断是代理配置还是上游本身。

## 最小 config.ly

在项目根目录创建：

```ly
http_port = 80
control_listen = "127.0.0.1:7030"

example.com {
    HeaderUps {
        X-Real-IP = "{ClientIp}"
        X-Forwarded-For = "{ClientIp}"
        X-Forwarded-Proto = "{Scheme}"
    }
    proxy = ["http://127.0.0.1:8080"]
}
```

站点名 `example.com` 同时是路由的 Host 条件。暂时不改 DNS，可以用 curl 手工发送 Host。

## 启动

源码模式：

```powershell
dotnet run -- run -c config.ly
```

发布包模式：

```powershell
dotnet LyWaf.dll run -c config.ly
```

## 验证

```powershell
curl.exe -i -H "Host: example.com" http://127.0.0.1/
```

你应该看到上游响应，并在响应头中看到 LyWaf。再打开 `http://127.0.0.1:7030` 登录控制台。忘记密码时执行：

```powershell
dotnet LyWaf.dll reset password
```

## 为什么控制台只监听本机

控制台能修改路由、防护和插件，风险远高于普通业务页面。默认绑定 `127.0.0.1`，远程管理应通过 SSH 隧道、VPN 或受限管理网络，不应直接暴露公网。

## 常见失败

| 现象 | 排查 |
|---|---|
| 404 或未匹配 | 请求是否带 `Host: example.com` |
| 502 | 从 LyWaf 主机直接请求上游地址 |
| 端口无法绑定 | 是否被其他进程占用，是否有低端口权限 |
| 页面空白 | 是否构建并部署了 `control_html` |

## 完成标准

- `dotnet build` 和前端生产构建均成功。
- 带正确 Host 的请求通过 LyWaf 到达测试上游。
- 未知 Host 不会误入该路由。
- 控制台只在预期管理地址访问。
- 停止上游后能够从日志区分路由成功与连接失败。

把启动命令、工作目录和验证请求保存下来，后续每次配置变更都能复用这组冒烟测试。
