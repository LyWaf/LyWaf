# 生产部署、监控、备份与故障排查

> 专栏第 13 篇。目标是把前十二篇的功能变成可持续运行、可回滚的生产系统。

## 推荐拓扑

```text
DNS/CDN -> LyWaf :80/:443 -> 私网业务节点
                |
                +-> 127.0.0.1:7030 控制台
                +-> 本地持久化数据与日志
```

业务端口只允许 LyWaf 访问。控制台保持本机或管理网绑定。

## 发布目录

```powershell
dotnet publish -c Release -o publish
Copy-Item config.ly publish/config.ly
```

前端变更应先运行 `npm run build`，确保 `control_html` 已更新。Windows 上运行中的 DLL 可能被锁定，升级前先优雅停止。

## systemd 示例

```ini
[Service]
WorkingDirectory=/opt/lywaf
ExecStart=/usr/bin/dotnet /opt/lywaf/LyWaf.dll run -c /opt/lywaf/config.ly
Restart=on-failure
RestartSec=5
User=lywaf
```

监听低端口时使用 capability 或外层端口转发，不要让整个进程长期以 root 运行。

## 必须监控

- 入口可用性、状态码和延迟分位数。
- 上游健康状态、连接数和超时。
- WAF/CC 命中和封禁增长。
- DuckDB、WAL、日志和防篡改基线磁盘占用。
- 进程内存、GC、CPU 和后台队列积压。
- 证书到期时间与 ACME 续期结果。

## 必须备份

```text
config.ly 与拆分配置
certs（加密保护私钥）
datas
plugin_data
.lywaf.*
```

防篡改目录必须整体备份。DuckDB 最好在优雅停止或检查点后复制。真正的备份标准是能够恢复登录、规则、统计、IP 组和基线，而不是“目录里有压缩包”。

## 变更和回滚

1. 配置进入版本控制，密钥除外。
2. 在测试实例加载相同配置。
3. 发布前保存程序、配置和数据快照。
4. 小流量验证后再扩大。
5. 回滚程序与回滚数据分开决策，避免旧程序读取不兼容的新数据。

## 常见故障

### 502/504

从 LyWaf 主机直连上游，检查地址、协议、DNS、健康检查、连接池和超时。

### 启动慢

按启动耗时日志定位。DuckDB 慢时检查数据库/WAL、强制关机恢复、磁盘和杀毒扫描，不要未经备份直接删除数据库。

### 路由错误

检查 Host、端口、Path 和 Method。用 curl 手工设置 Host，避免只访问 IP 得出错误结论。

### 防护误报

先切回 Observe 或暂停具体规则，保留命中样本后收窄作用字段和路径，不要一次性关闭整个防护体系。

### 防篡改未收集

请求必须真正经过 LyWaf，网站 authority 与端口必须匹配。目录规则只在实际路径首次访问后收集。

## 上线前最后演练

- 合法请求和攻击样例。
- 单节点下线和全部上游失败。
- CORS 预检与凭据请求。
- 黑名单、白名单、限速和恢复。
- 防篡改变更、差异查看和基线确认。
- 优雅停止、重启和完整恢复。

## 专栏总结

我们从一个最小反向代理开始，逐步建立了 TLS、路由、安全策略、访问控制、CORS、防篡改、插件和生产运维体系。真正可靠的 WAF 不是规则越多越好，而是每项能力都有明确边界、可观察数据、变更流程和回滚路径。

## 最终交付物

完成专栏后应保存：版本化配置、部署脚本、服务定义、监控告警、备份与恢复步骤、规则变更记录、插件清单、容量基准和回滚包。这些内容应由团队共享，而不是只存在某位维护者的终端历史中。

## 持续改进

每次故障和误报都应产生新的自动检查、测试样本或监控指标。按周期演练上游故障、证书续期、配置回滚、数据恢复和插件停用，确保文档在真实环境中仍可执行。
