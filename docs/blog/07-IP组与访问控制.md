# IP 组、黑白名单与真实客户端 IP

> 专栏第 8 篇。目标是把零散 IP 规则整理成可复用、可审计的访问策略。

## 零散名单的问题

办公出口、运维主机、CDN 回源段经常被多个规则引用。把地址复制到每条规则中，后续变更很容易漏掉。IP 组将“地址集合”和“访问动作”分开维护。

典型分组：

```text
office-networks  办公网和远程接入出口
ops-hosts        堡垒机、监控、发布节点
cdn-origin       CDN 官方回源网段
known-abuse      已确认恶意地址
```

## 支持格式

```text
192.0.2.10
198.51.100.0/24
2001:db8:1200::/48
```

系统校验 IPv4、IPv6 和 CIDR，去除重复项。名称最长 64 个字符且不能重复。运行数据保存在输出目录的 `datas/ip-groups.json`。

## 创建和使用

在控制台的黑白名单/IP 组页面：

1. 创建组并填写名称、负责人和用途。
2. 每行输入一个地址或 CIDR。
3. 在访问控制规则中引用该组。
4. 使用组内和组外地址分别验证。

管理后台适合使用允许列表：

```text
/admin/* -> 只允许 office-networks 与 ops-hosts
```

公开 API 更适合拒绝明确恶意组，其他请求继续交给 WAF、认证和限速。

## 白名单不是万能通行证

全局白名单可能跳过后续地理或访问检查。不要把整个云厂商、运营商或 CDN 网段加入全局白名单，只因其中有一个合法地址。

优先使用路径级、用途明确的窄范围允许策略。

## 真实 IP 信任链

当 CDN 位于 LyWaf 之前：

```text
客户端 -> CDN -> LyWaf -> 应用
```

客户端可自行构造 `X-Forwarded-For`。LyWaf 只能信任来自已知 CDN 地址的转发头，并按约定取正确一段。否则攻击者可能伪造办公网 IP，所有限速统计也会失真。

## 审计与备份

- 临时地址必须记录失效时间。
- 删除组前检查规则引用。
- 每季度复核管理网和全局白名单。
- 发布时持久化 `datas/ip-groups.json`。
- 大批量修改前备份旧文件并准备回滚。

## 读者实验

创建包含单 IP、IPv4 CIDR 和 IPv6 CIDR 的测试组，分别应用到全局与路径规则。验证网段边界、规则冲突和真实代理来源，再修改备注名称确认引用不受影响。删除前检查引用并演练文件恢复。

## 完成标准

系统识别的客户端 IP 与访问日志一致；白名单范围足够小；外部订阅更新失败时仍保留最近有效集合；所有修改可审计和回滚。
