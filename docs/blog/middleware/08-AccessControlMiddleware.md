# AccessControlMiddleware：IP、地理与连接限制

## 位置

位于高优先级插件之后、请求深度日志和 WAF 之前。明显不允许的来源在读取 Body 和执行昂贵规则前被拒绝。

## 第一阶段：访问准入

中间件通过 `RequestUtil.GetClientIp` 获取客户端 IP，并调用 AccessControlService 检查：

- 全局 IP 黑白名单。
- 路径级 IP 限制。
- 全局地理位置策略。
- 路径级地理位置策略。

拒绝时记录地区、规则和拦截事件，设置日志标记，再使用统一错误模板返回，不调用下游。

## 第二阶段：连接限制

启用 ConnectionLimit 后，从当前 RouteModel 获取 ClusterId 作为目标标识，并按 IP、目标和 Path 获取连接额度。

获取失败返回配置状态码；获取成功调用下游，并在 `finally` 中释放额度。

## 为什么 finally 必须存在

下游可能正常返回、短路或抛异常。连接额度如果只在成功路径释放，少量异常请求就会让限制计数永久占满。

## 白名单顺序

白名单通常可以直接允许并跳过部分地理检查。它是高权限配置，应尽量限定路径和小网段，不应把大范围云厂商地址加入全局白名单。

## 真实 IP 风险

该中间件是 IP 黑白名单、Geo 和连接限制共同的入口。若无条件信任客户端 X-Forwarded-For，攻击者可伪造白名单来源；若完全不读取可信代理头，所有用户又可能显示为 CDN IP。

## 排障

- 全部用户被限成同一来源：真实 IP 链配置错误。
- 合法 IP 被拒绝：检查 CIDR、IPv4/IPv6 和路径规则。
- 连接数不下降：检查下游长连接和异常释放。
- 拒绝无事件：确认请求确实进入代理 Endpoint。

## 规则冲突处理

必须明确白名单、黑名单、路径规则和地理规则的优先级，并通过测试固定行为。IP 组更新后引用方应读取最新集合；删除组前要检查是否仍被策略引用。

## 验证方法

从允许、拒绝和可信代理后的客户端地址请求同一路径，覆盖 IPv4、IPv6 和 CIDR 边界。对连接限制并发建立长请求，确认超额请求被拒绝，已有请求结束后额度恢复。
