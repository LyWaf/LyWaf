# WebTamperMiddleware：网页安全基线

## 所属与位置

它不是核心固定中间件，而是 `web-tamper` 系统插件在 High/Highest 阶段注册的代理中间件。它位于压缩内层、访问控制外层。

## 跳过条件

- 内部检查请求带 `X-LyWaf-Tamper-Check`：移除标志并继续，防止递归。
- 插件不是 Running/Initialized：继续。
- 当前网站和路径未匹配保护资源：继续。

## 命中资源后的流程

1. 保存原始响应流与客户端 Accept-Encoding。
2. 移除 Accept-Encoding，避免上游压缩影响内容比较。
3. 创建异步顺序访问的临时文件，将 Response Body 指向文件。
4. 调用下游，收集实际响应。
5. 非 2xx 或超过最大内容限制时原样流回客户端。
6. 对临时文件增量计算 Hash。
7. 记录目录规则实际路径，并惰性加入后台检查队列。
8. Hash 与基线不一致时改为读取基线文件。
9. 设置 `X-LyWaf-Tamper-Protected: baseline`，移除 ETag 和 Last-Modified。
10. 使用文件流复制最终内容。

## 清理阶段

`finally` 恢复 Accept-Encoding 和原始 Body，异步关闭临时文件，再尝试删除。任何分支都不能遗留 Body 指向已释放文件。

## 为什么使用文件而不是内存

受保护的 JS、CSS 或 HTML 可能较大。临时文件、文件句柄和增量 Hash 将内存保持在固定缓冲量，配合最大文件限制抵抗异常大响应。

## 与压缩的关系

上游比较使用未压缩内容；选定安全基线后，外层 ResponseCompress 再按客户端能力压缩。这样同一内容不会因 gzip/br 表示不同而误报。

## 排障

- `/*` 未收集：请求必须实际经过 LyWaf 且 authority 匹配。
- 响应未替换：检查插件状态、资源 Enabled、状态码和大小上限。
- 临时文件积累：检查异常退出、文件权限和清理失败日志。
- 动态页面频繁变化：应排除，不适合静态基线。

## 惰性目录规则

`/*`、`/static/*` 或路由模板命中时，真实访问路径只负责入队。后台对标准化后的站点和路径做一分钟频率限制，再流式访问远端并创建独立基线。排除项仍可手动检查，但不会自动替换响应。

## 验证矩阵

依次测试首次收集、内容一致、内容变化后返回安全基线、接受新基线、排除、恢复和删除。另测非标准端口、HTTPS 失败回退 HTTP、超时、大响应、并发访问同一路径和进程重启。检查临时目录、文件句柄和远端请求次数始终有界。
