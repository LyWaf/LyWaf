# 插件代理阶段：优先级与插入点

## 为什么它不是单个类

`UseLyWafPluginsInProxyHigh` 和 `UseLyWafPluginsInProxyNormal` 会让 PluginManager 按元数据优先级注册多个插件中间件。这里是动态插入阶段，不对应唯一 Middleware 类。

## 两个插入点

### 高优先级阶段

包含 `Highest` 与 `High`，位于 ResponseCompress 后、AccessControl 前。适合必须包住核心安全链或完整上游响应的插件，例如 WebTamper。

### 普通/低优先级阶段

包含 `Normal`、`Low`、`Lowest`，位于核心安全和流控之后、SimpleRes/FileProvider 之前。适合分析、审计和普通响应改写。

## 插件顺序意味着什么

请求按注册顺序进入，响应反向返回。一个高优先级插件既能在核心安全前观察请求，也能在核心安全和上游完成后观察响应。

优先级越高不代表能力越强，只代表包裹范围更外。无理由使用 Highest 会扩大插件故障影响。

## 插件短路

每个插件可以自行决定是否调用 next。短路插件必须产生完整状态码、Header 和 Body，并确保恢复它包装的流。插件异常不应传播到主代理，除非设计目标就是阻止请求。

## 生命周期与运行状态

PluginManager 发现插件、注册服务、初始化并启动。业务中间件还应检查插件状态，避免已禁用插件继续执行。WebTamperMiddleware 就会检查 Running/Initialized。

## 设计检查表

- 需要看到安全检查前还是后的请求？
- 需要看到 SimpleRes/FileProvider 的响应吗？
- 是否会读取或替换 Body？
- 是否有大小、超时、队列和并发限制？
- Disable/Stop 时是否释放后台任务和句柄？

## 排障

插件代码未执行时检查插件状态、优先级分组和 ConfigureProxyPipeline 是否被调用。执行顺序异常时查看 PluginManager 的排序，而不是依赖文件名或类发现顺序。

## 动态启停限制

插件生命周期可以运行时启停，但 ASP.NET Core 已构建的管线不会重新插入或移除中间件。插件中间件必须读取动态状态并旁路；首次启用一个启动时未挂载的中间件插件则需要重启。

## 验证方法

创建两个只记录进入和退出顺序的测试插件，赋予不同优先级，确认请求方向和响应方向相反。再禁用其中一个，检查其服务停止且请求处理旁路，最后重启验证管线结构。
