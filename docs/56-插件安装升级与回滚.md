# 插件安装、升级与回滚

## 包格式

插件发布为 `.lyplugin` ZIP 包，根目录必须包含 `plugin.json`。清单声明 `id`、`version`、`entryAssembly`、`sdkVersion`、`dataVersion`、`frontendVersion` 和逐文件 SHA-256。签名载荷覆盖这些版本字段和排序后的文件哈希，算法为 RSA-SHA256/PKCS#1。

```json
{
  "id": "example-plugin",
  "version": "1.2.0",
  "entryAssembly": "Example.Plugin.dll",
  "sdkVersion": "1.0.0",
  "dataVersion": 2,
  "frontendVersion": "1.2.0",
  "files": {
    "Example.Plugin.dll": "SHA256_HEX",
    "frontend/index.html": "SHA256_HEX"
  },
  "signingKeyId": "release-2026",
  "signature": "BASE64_RSA_SIGNATURE"
}
```

## 安装过程

控制台以流方式把包发送到 `POST /api/plugins/install`。宿主限制总大小、拒绝路径穿越、逐文件核对哈希并按配置验证签名。验证成功后写入 `plugins/<id>/versions/<version>`，最后原子替换 `current.json`。旧版本目录被保留，但发现器只加载当前指针，安装和升级都明确返回 `requiresRestart=true`。

压缩包大小、解压后总量和文件数量分别由 `MaxPackageBytes`、`MaxExtractedPackageBytes`、`MaxPackageFiles` 限制。包不得携带 `LyWaf.PluginSdk.dll`；宿主加载上下文始终复用自己的契约程序集，避免同名接口因程序集上下文不同而无法识别。

启动加载时还会比较 DLL 的 `PluginMetadata.Version`、`DataVersion`、`FrontendVersion` 与清单；不一致的前后端组合会被拒绝。生产环境应设置 `RequireSignedPackages=true` 并配置 `TrustedSigningKeys`。

## 数据迁移

当 `PluginMetadata.DataVersion` 变化时，插件实现 `IPluginDataMigrationProvider`，提供从当前版本到目标版本的完整迁移链。迁移在初始化前执行，通过 `IPluginStorage` 流式访问专属目录；链中断、循环或失败都会阻止插件启动。降级同样需要显式反向迁移，避免代码回滚后读取不兼容数据。

## 回滚

`POST /api/plugins/{pluginId}/rollback` 把当前指针切换到上一安装版本并要求重启。回滚不会删除新版本；若旧版本需要降低数据版本，必须包含反向迁移。系统插件不能通过该流程替换。
