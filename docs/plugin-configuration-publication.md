# 插件配置发布与并发保护

通用插件配置保存入口现在区分“写入文件”与“已在请求配置中生效”。发布协调逻辑位于 `PluginConfigurationPublisher`，ControlApi 负责权限、请求字段准备和调用既有补丁存储设施。

## 调用方式

1. `GET /api/v1/plugins/{id}/config` 读取配置及 `version`。
2. 可选调用 `POST /api/v1/plugins/{id}/config/validate`，请求体仍是扁平字符串字典。
3. 保存时调用 `POST /api/v1/plugins/{id}/config`，携带 `If-Match: <version>`，请求体保持不变。

```http
POST /api/v1/plugins/image-process/config
Content-Type: application/json
If-Match: <读取配置时返回的 version>

{"Enabled":"true","DefaultQuality":"80","SupportedFormats:0":"png"}
```

这是完整配置提交，不是局部字段 PATCH；示例未填写的字段会回到模型默认值。实际后台提交整个编辑表单。空数组/字典用对应字段值 `""` 表示，例如 `{"SupportedFormats":""}`，不会重新拼接默认元素。

旧客户端也必须先读取版本。缺少版本或版本过期返回 HTTP 409，且不会写入。后台已携带版本，不会自动覆盖冲突或丢弃用户尚未保存的编辑内容。

## 发布流程

- 读取配置与版本、发布操作共用已有配置补丁互斥锁。
- 版本指纹包含当前配置和主配置/补丁文件内容；进程重新启动后需要重新读取版本。
- 对支持分层配置的插件，在写文件前验证候选全局配置与所有站点、路径的合并结果。
- 使用已有配置版本服务写入补丁，重载后核对运行快照的指纹。
- 若重载拒绝候选，或运行快照与候选不一致，使用已有版本回滚机制恢复原补丁并重新加载。首次创建的失败补丁会删除。
- 损坏的现有补丁会报错，不会当成空文件覆盖。

完整插件快照保存在补丁文件的 `PluginConfigSnapshots` 中，普通 `PluginConfigs` 同时保留供旧入口读取。已接入的分层解析器优先读取完整快照，避免多配置源按数组索引合并导致旧数组尾部重新出现。快照属于全局覆盖，站点/路径仍在其上继续覆盖。

## 返回状态

| status | HTTP | 含义 |
| --- | --- | --- |
| applied | 200 | 已接入分层配置的插件运行快照与候选一致 |
| restart_required | 200 | 未接入插件的配置已保存，需要重启后确认生效 |
| version_conflict | 409 | 版本缺失或过期，没有写入 |
| validation_failed | 400 | 合并校验失败，没有写入 |
| publish_failed | 500 | 写入、重载或生效核对失败，需要检查日志及配置版本 |

`applied` 仅描述请求配置快照，不表示插件生命周期一定处于运行状态；后台禁用插件仍然有效。显式标记 `RequiresRestart` 的字段依旧拒绝在线修改，尚未提供待重启候选暂存功能。

## 边界

这里的并发保护覆盖当前进程中使用共享补丁锁的管理操作，不是跨进程锁，也不能阻止外部编辑器在检查之后直接修改配置文件。它不提供整个应用的事务性重载保证；其他模块的配置监听器、插件生命周期和代理路由仍有独立行为。

失败时会尝试回滚，但磁盘故障等也可能导致回滚失败，所以返回 `publish_failed` 不等同于保证回滚成功，必须查看服务日志。暂未增加专门的插件版本历史页面。

测试包括并发版本冲突、全局合法但站点合并非法、写入未生效、实际补丁发布/恢复、重启读取数组，以及编辑器短数组和空数组往返。
