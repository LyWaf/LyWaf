# 反向代理响应缓存

LyWaf 的响应缓存用于减少可缓存 GET 请求对上游的压力。元数据保存在进程内存，正文以独立文件流式写入磁盘；进程重启后不恢复旧索引，并会清理缓存目录中的孤立文件。

## 安全默认值

缓存默认关闭。即使启用，以下请求或响应也不会进入缓存：

- 非 GET/HEAD 请求；首次 HEAD 只回源，不创建空正文缓存。
- 带 `Authorization` 的请求，除非显式设置 `CacheAuthenticated = true`。
- 带 `Range` 的请求，避免把 206 片段当成完整对象。
- 带 `Cache-Control: no-store` 的请求。
- 带 `Set-Cookie`、`Cache-Control: private/no-store` 或 `Vary: *` 的响应。
- 不在 `StatusCodes` 白名单中的响应。

缓存命中会返回 `X-LyWaf-Cache`，可能值为 `HIT`、`MISS`、`STALE`、`REVALIDATED` 或 `STALE-ERROR`。

## 配置

```ly
ResponseCache {
    Enabled = false
    Directory = "datas/response-cache"
    MaxBodyBytes = 33554432
    MaxCacheBytes = 1073741824
    DefaultTtlSeconds = 60
    StaleWhileRevalidateSeconds = 30
    StaleIfErrorSeconds = 300
    CacheAuthenticated = false
    Methods = ["GET", "HEAD"]
    StatusCodes = [200, 203, 204, 301, 404]
}

example.com {
    /assets/* {
        ResponseCache { Enabled = true TtlSeconds = 300 }
        reverse_proxy http://127.0.0.1:8080
    }
}
```

路由级 `Enabled` 覆盖全局开关，`TtlSeconds` 覆盖默认 TTL。上游 `s-maxage`、`max-age` 和 `Expires` 优先于默认 TTL；`no-cache` 会保存内容但要求下次条件回源。

## Key 与 Vary

基础 Key 由小写 Host（保留非标准端口）、PathBase、Path 和原始 QueryString 组成，GET 与 HEAD 共用。首次响应声明 `Vary` 后，所列请求头值加入变体 Key。不同语言、内容协商版本等不会互相串用。

Query 参数顺序不会自动归一化，`?a=1&b=2` 与 `?b=2&a=1` 是两个 Key。这避免在不了解重复参数语义时做错误合并。

## 过期与回源

1. 新鲜期内直接流式读取磁盘正文。
2. SWR 窗口内立即返回旧内容，并向有界后台队列加入一次刷新请求。
3. SWR 窗口外使用 ETag 或 Last-Modified 条件回源；上游返回 304 时只刷新元数据有效期。
4. 回源抛出异常或返回 5xx，且仍在 `StaleIfErrorSeconds` 内时返回最后正常内容。

同一基础 Key 使用单个异步锁，热点首次未命中只允许一个请求回源；最后一个等待者离开后锁对象会从内存表移除。后台刷新按完整变体 Key 去重，只复制条目声明的 `Vary` 请求头，不复制 Cookie 或 Authorization。

## 文件与容量

响应先写入临时文件。达到 `MaxBodyBytes` 后，中间件立即把已写内容流向客户端并切换为直通，响应不会进入索引。总容量超过 `MaxCacheBytes` 时按最近访问时间淘汰正文。

缓存目录应位于本地快速磁盘并限制操作系统权限。不要与多实例共享同一目录；多节点各自缓存，失效操作需要在每个节点执行。

## 清理 API

控制端口提供 JWT/Basic Auth 保护的 API：

- `GET /api/v1/response-cache`：只返回元数据，不读取正文。
- `POST /api/v1/response-cache/purge`：按精确 `Key`、精确 `Host` 和 `Path` 前缀组合清理。

请求至少提供一个条件：

```json
{ "host": "example.com", "path": "/assets/" }
```

空条件会返回 400，避免误清全库。

## 中间件顺序

缓存位于响应压缩内层、防篡改及代理响应处理外层。写入磁盘的是已经过防篡改确认的未压缩内容，命中后再依据当前客户端 `Accept-Encoding` 压缩。认证响应默认绕过；Range 请求交给上游或文件服务处理，不从完整缓存切片。

## 监控

- `lywaf_response_cache_requests_total{outcome}`：固定结果类型计数。
- `lywaf_response_cache_entries`：当前内存索引条目数。
- `lywaf_response_cache_bytes`：当前磁盘正文总字节数。

Prometheus 标签不包含 Host、Path 或 Key，避免缓存对象数量直接变成指标基数。
