# 生产上线检查清单

## 网络

- [ ] DNS 已指向 LyWaf 入口。
- [ ] 仅开放必要的 80/443 或业务端口。
- [ ] 上游端口不直接暴露公网。
- [ ] 控制台绑定 `127.0.0.1` 或受控管理地址。
- [ ] CDN/外层代理的真实 IP 信任链已验证。

## TLS

- [ ] 每个 HTTPS 域名都有匹配证书和私钥。
- [ ] 私钥权限最小化且未提交仓库。
- [ ] 证书续期流程已验证，不只是假设可用。
- [ ] HTTP 到 HTTPS 和 ACME Challenge 不冲突。

## 路由与上游

- [ ] Host、Path、Method 均命中预期路由。
- [ ] 上传、下载、WebSocket、长请求已测试。
- [ ] 多上游健康检查真实反映服务状态。
- [ ] 超时和最大连接数符合业务特征。
- [ ] 转发头不会被客户端伪造覆盖。

## 安全

- [ ] WAF 新规则已先观察后阻断。
- [ ] 管理路径使用允许列表，不只依赖密码。
- [ ] CC 和限速已按动态 API、静态资源区分。
- [ ] 白名单和排除项有负责人及失效时间。
- [ ] CORS 只允许必要 Origin、Method 和 Header。
- [ ] 防篡改规则排除了动态和个性化响应。

## 数据

- [ ] `datas`、`plugin_data`、认证与规则状态文件已持久化。
- [ ] 防篡改元数据和基线文件一起备份。
- [ ] DuckDB 数据保留和磁盘容量已评估。
- [ ] 已进行恢复演练，不只是创建备份。

## 运维

- [ ] 进程由 systemd、Windows Service 或可靠守护程序管理。
- [ ] 日志轮转、磁盘告警和时间同步已配置。
- [ ] 监控入口状态、上游状态、错误率和延迟。
- [ ] 有可执行的配置回滚版本。
- [ ] 已验证优雅停止，避免统计和数据库未刷写。

## 发布验收

```powershell
curl.exe -i -H "Host: example.com" http://127.0.0.1/health
curl.exe -k -i --resolve example.com:443:127.0.0.1 https://example.com/health
```

最后进行一次合法请求、攻击样例、限速、黑名单、CORS 预检和防篡改变更演练，确认控制台事件、日志和客户端响应一致。

## 容量与故障演练

- [ ] 使用预期峰值测试 CPU、内存、句柄和延迟。
- [ ] 大请求、大响应和慢客户端不会形成无界缓冲。
- [ ] 停止单个上游后能正确摘除并恢复。
- [ ] 模拟磁盘接近满、远端插件超时和数据库查询慢。
- [ ] WebSocket、下载和长请求能够优雅关闭。

## 发布记录与放行

记录程序、配置和插件版本、备份点、操作人及验证结果。控制端公网暴露、无法回滚、备份未验证、核心路由失败或大面积误报都应阻止上线；临时放宽策略必须有恢复负责人和截止时间。
