# 支持周期与安全发布

## 支持范围

仓库根目录 `SUPPORT.md` 是运行环境、协议、浏览器和插件契约的简明支持矩阵。项目以 .NET 9 为后端基线，CI 在 Windows 与 Linux 构建测试；标记为“生成包但待部署验证”的平台不能等同于完整支持。

升级默认覆盖当前版本与前一个次版本。跨越更多版本时先在隔离环境恢复生产配置和数据副本，逐版本执行迁移。插件必须声明与宿主契约的兼容版本，不能仅凭 DLL 可以加载判断兼容。

## 自动验证层次

| 层次 | 命令或入口 | 目标 |
|---|---|---|
| 单元与 loopback 集成 | `dotnet test tests/LyWaf.Tests/LyWaf.Tests.csproj` | 配置、协议、安全边界和真实本机数据路径 |
| 前端构建 | `npm ci && npm run build` | TypeScript 契约、路由和生产资源 |
| 性能矩阵 | `benchmarks/run.ps1` | 吞吐、延迟、错误和资源变化 |
| 长时间运行 | `benchmarks/soak.ps1` | 数小时到七天的泄漏、句柄、GC 和错误趋势 |
| 故障注入 | Benchmark Server 的 `/fault/*` | 500、延迟和连接中断下的重试、熔断与旧缓存 |
| 发布冒烟 | `tools/release.ps1` | Runtime 包、内部清单和归档校验和 |

故障测试必须使用隔离上游。`/fault/status/{code}` 返回指定 4xx/5xx，`/fault/delay/{milliseconds}` 模拟慢上游，`/fault/abort` 模拟连接中断。测试结束后确认在途请求归零、连接和文件句柄回落、后台队列有界、停止过程完成。

长稳测试示例：

```powershell
./benchmarks/soak.ps1 -Url http://127.0.0.1:8080/small -Hours 8 -Concurrency 128
```

结果与环境信息分别写入 `benchmarks/results`。正式验收应同时采集 `/metrics`，至少观察进程内存、托管堆、GC、线程、句柄、请求错误、上游健康、队列拒绝和 DuckDB 失败。

## 安全响应

根目录 `SECURITY.md` 定义私密报告、影响分级、修复、回归测试和协调披露流程。CVE 处理必须记录“受影响、不可达或不适用”的依据；升级依赖后仍要验证 WAF、解析器、TLS、压缩、文件路径和插件边界。

## 可复现发布

```powershell
./tools/release.ps1 -Version 1.2.3 -Runtime win-x64,linux-x64
```

默认会为每个 Runtime 执行依赖还原。只有流水线已经用相同项目和 Runtime 完成还原时才使用 `-NoRestore`；该参数不会下载缺失依赖。

脚本启用 .NET 确定性构建，按固定路径顺序创建 ZIP，并把 ZIP 条目时间固定为 UTC 2000-01-01。每个包内含逐文件 `SHA256SUMS`，输出目录另有归档级校验和。相同源码、SDK、依赖锁、Runtime 和参数是复现前提；SDK 或依赖变化不应期待二进制相同。

发布前必须在干净检出中执行 CI，保存 SDK 版本和 Git 提交，核对包中没有 `config.ly` 私有配置、DuckDB、日志、认证文件、证书私钥或插件运行数据。升级和回滚遵循第 32 章的候选探针与版本指针流程。
