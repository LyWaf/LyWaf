# 性能基准

仓库内的 `benchmarks` 提供固定上游、负载器、目标矩阵及 Nginx/Caddy 对照配置。基准的目标不是给出脱离硬件的宣传数字，而是在同一机器、TLS 参数、上游和负载下产生可复核结果。

## 组件

| 文件 | 作用 |
|---|---|
| `LyWaf.Benchmark` | `serve` 提供标准响应；`load` 产生有界并发负载 |
| `targets.example.json` | 定义 LyWaf 功能组合和对照代理地址 |
| `run.ps1` | 运行矩阵并写入 JSON Lines 结果和环境快照 |
| `compose.yaml` | 启动同一上游下的 Nginx 和 Caddy |
| `nginx.conf`、`Caddyfile` | 本机运行对照代理时使用 |

## 标准场景

- `small`：32 字节响应，观察代理固定开销和高并发吞吐。
- `large`：1 MiB 二进制响应，观察带宽、内存和背压。
- `slow-upstream`：上游等待 100ms，观察连接与排队容量。
- `slow-client`：客户端分块读取并等待，检查是否形成无界缓冲。
- `websocket`：每次建立连接并完成一轮双向回显。

HTTP 客户端可通过 `--protocol 1.1` 或 `--protocol 2` 强制协议版本；HTTPS 由目标 URL 决定。HTTP/2 对照必须确认最终协商确实为 HTTP/2，不能把允许降级的结果标成 HTTP/2。

## 启动标准上游和对照代理

```powershell
docker compose -f benchmarks/compose.yaml up -d --build
```

Docker 不可用时，可本机启动：

```powershell
dotnet run --project benchmarks/LyWaf.Benchmark -- serve --urls http://127.0.0.1:19080
nginx -c D:/my/LyWaf/benchmarks/nginx.conf
caddy run --config D:/my/LyWaf/benchmarks/Caddyfile --adapter caddyfile
```

## 准备 LyWaf 目标

所有实例必须指向同一个 `127.0.0.1:19080` 上游，并分别启用：

1. 纯代理：关闭 WAF、站点日志、压缩和防篡改。
2. WAF：使用固定规则集，记录规则版本和数量。
3. 日志：固定输出格式、介质和刷写策略。
4. 压缩：对 `/compress` 使用相同算法和级别。
5. 防篡改：使用相同规则；预热基线后再开始计时。

HTTPS 对照使用同一证书、密钥、TLS 版本和 cipher。不要同时运行多个被测代理争用同一 CPU 核；矩阵中的目标可分批保留。

## 执行

复制 `targets.example.json` 为 `targets.json`，删除未启动的目标并修正端口，然后运行：

```powershell
./benchmarks/run.ps1 -Duration 30 -Concurrency 128
```

自签名测试证书的目标设置 `"insecure": true`；该选项只能用于隔离的基准环境。为 Nginx/Caddy 目标填写 `"processId": 1234` 后，脚本会记录其进程 CPU、Working Set、Private Memory、线程和句柄前后值。

结果写入 `benchmarks/results`：

- `*-environment.json`：操作系统、架构、CPU 数、.NET 版本和参数。
- `*-results.jsonl`：每个目标和场景的吞吐、P50/P95/P99、字节数、错误率、错误分类，以及 LyWaf 资源指标前后快照。

LyWaf `/metrics` 暴露进程 CPU 秒、Working Set、托管堆、各代 GC 次数、线程和句柄。CPU 与 GC 使用测试前后差值，内存、线程和句柄同时关注峰值；正式采集可提高到每秒一次，不能只记录结束值。

## 测量规则

每个场景先预热 30 秒，再至少测量 3 轮，每轮 30 秒以上，报告中位数并保留全部原始结果。固定 CPU 电源策略，关闭调试日志和无关任务。任何非零错误都必须按 `ErrorReasons` 解释，不能仅比较吞吐。

Nginx/Caddy 对照必须使用相同上游、监听协议、TLS 和访问日志设置。功能不等价时明确标注，例如只比较纯代理或压缩，不把缺少 WAF 的配置与 LyWaf WAF 场景直接排序。
