# IP 组与访问控制

## 为什么使用 IP 组

相同的办公网、运维机、CDN 回源段或攻击情报地址可能被多条规则引用。IP 组将 IP/CIDR 集合与规则解耦，避免重复维护造成遗漏。

典型分组：

- `office-networks`：办公出口和 VPN 网段。
- `ops-hosts`：堡垒机、监控和发布节点。
- `cdn-origin`：允许访问源站的 CDN 回源段。
- `known-abuse`：确认的恶意地址或网段。

## 支持的数据

每个组包含名称、备注和多条 IPv4/IPv6 地址或 CIDR。示例：

```text
192.0.2.10
198.51.100.0/24
2001:db8:1200::/48
```

系统会去除空项和重复项，并拒绝非法地址或超出范围的掩码。组名最长 64 个字符且不允许重复。

## 创建流程

1. 在控制台进入黑白名单/IP 组管理。
2. 创建组并填写能说明所有者和用途的备注。
3. 每行输入一个 IP 或 CIDR。
4. 保存后在访问控制规则中引用该组。
5. 使用组内和组外测试地址分别验证允许与拒绝结果。

## 规则设计

白名单应尽量窄，并明确作用范围。全局白名单可能绕过地理和其他访问检查，不应把大范围云厂商网段加入全局白名单。

```text
管理后台：仅允许 office-networks + ops-hosts
源站入口：仅允许 cdn-origin
公开 API：拒绝 known-abuse，其余交给 WAF 和限速
```

IP 组是动态运行数据，保存在程序输出目录的 `datas/ip-groups.json`。修改 `config.ly` 不会覆盖它，迁移和备份时必须一并复制。

## 真实 IP 注意事项

若 LyWaf 前还有 CDN 或负载均衡器，不能无条件信任客户端提供的 `X-Forwarded-For`。应只从可信代理读取转发头，否则攻击者可以伪造白名单 IP。

## 变更管理

- 备注中记录负责人、工单和失效时间。
- 临时地址到期后及时删除。
- 删除组前检查引用关系。
- 大批量更新后保留旧版本备份，以便回滚。
- 每季度审计管理网和全局白名单。

## 排障

| 现象 | 检查项 |
|---|---|
| 合法用户被拒绝 | 实际出口 IP、CIDR 掩码、规则作用路径 |
| 黑名单不生效 | 是否被更高优先级白名单放行 |
| 所有用户显示同一 IP | 真实 IP 转发链配置错误 |
| 重启后组丢失 | `plugin_data` 不可写或部署未持久化 |

## 数据规范化

入库前去除空格、规范 IPv6 并验证 CIDR。重复项合并，重叠网段提示用户；备注名称与稳定组 ID 分离，修改备注不改变引用关系。

## 优先级与边界测试

构造同时命中白名单、黑名单和路径规则的地址，确认系统优先级。测试网段首尾、IPv4 映射 IPv6 和代理后的真实 IP。删除组前检查引用，避免策略静默失效。

## 备份审计

备份 IP 组及引用配置，记录创建、修改、删除和导入差异。外部订阅更新失败时保留最近有效内容，不要把组替换为空。
