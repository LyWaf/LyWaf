# 插件系统

LyWaf 提供基于 `ILyWafPlugin` 接口的可扩展插件架构。

从零开发后端插件、统一 API 和控制台页面，请阅读 [插件开发完整子专栏](blog/plugins/README.md)。

## 生命周期

1. **ConfigureServices** — 注册插件 DI 服务
2. **Initialize** — 一次性初始化
3. **Start** — 开始运行
4. **Stop** — 优雅关闭

## 插件能力

- 按优先级注入中间件（Highest → Lowest）
- 自定义代理管线（ConfigureProxyPipeline）
- 通过 REST API 执行自定义 Action
- 插件间事件总线（IPluginEventBus）
- 元数据：版本、作者、描述、依赖

## 内置插件

| 插件 | 类型 | 说明 |
|------|------|------|
| AnalysisPlugin | 系统 | 流量分析与报表 |
| ImageProcessPlugin | 系统 | 图片缩放/裁剪/格式转换 |
| WebTamperPlugin | 系统 | 网页基线、防篡改中间件、管理页面和插件 API |
| CustomHeaderPlugin | 示例 | 注入/修改响应头 |
| RequestLoggerPlugin | 示例 | 高级请求日志 |

## 开发扩展

实现 `ILyWafPlugin` 接口，放入 Plugins 目录，即可被 PluginManager 自动加载。插件可通过 `IPluginContext` 访问服务容器和配置。插件专属控制台接口应实现 `IPluginApiHandler`，统一通过 `/api/plugins/{pluginId}/proxy/{path}` 转发。

后台插件通过 `IPluginContext.Tasks` 获取 `IPluginTaskCoordinator`。提交任务前用稳定幂等键调用 `TryStart`，结束时调用 `Complete`，任务状态会持久化并可选复制到其他节点。该机制是可用性优先的最终一致方案，不能保证跨节点外部副作用只执行一次。不可重复操作必须由业务目标提供幂等接口并采用明确的单写者协议；当前不新增数据库，也不把验证码专用权威存储当成通用任务事务。完整示例见[分布式运行状态](36-分布式运行状态.md)。

## 发现与启用规则

管理器扫描已加载程序集和插件目录中的 DLL。所有已发现插件先注册 DI，启用插件才进入初始化、启动和管线配置。启用状态依次参考插件配置中的 `Enabled`、禁用列表、系统插件标记和 `EnabledByDefault`。

系统插件不能被同 ID 外部插件覆盖。外部程序集可独立加载和卸载，但新增 DI 注册、中间件结构或前端页面后仍应重启宿主。

## 前后端边界

后端插件负责能力、状态和数据；前端插件目录在 Vite 构建期注册页面。管理入口由 `page-link` Action 指向 `/plugins/{id}`，页面使用 `pluginProxyApi(id)`，核心控制台不增加插件专用业务路由。

## 安全要求

插件网络访问必须限制超时、频率和响应大小；后台队列必须有界；本地大文件使用句柄和流；停止时释放订阅、任务和句柄。插件异常不应拖垮代理主流程。

安装后依次验证发现日志、管理页状态、统一 API、业务请求处理和优雅停止。完整代码与发布流程见 [插件开发子专栏](blog/plugins/README.md)。
