# 配置版本与原子应用

LyWaf 的控制台配置写入采用“候选校验、版本归档、原子替换、运行时重载”流程，避免无效或只写入一半的配置破坏当前服务。

## 处理流程

1. 控制台提交主配置草稿或运行时补丁。
2. 主配置先执行语法解析和应用配置转换；补丁必须是 JSON 对象。
3. 首次修改现有文件时，系统自动创建 `baseline` 基线版本。
4. 候选内容写入版本归档并更新版本索引。
5. 候选内容通过同目录临时文件落盘、刷写后原子替换目标文件。
6. 请求保存并重载时，`IConfigurationRoot.Reload()` 构建新的运行时配置。
7. 配置提供器加载失败时恢复之前的 `Data` 快照，现有请求继续使用最近有效配置。

无效候选在第 2 步被拒绝，不会覆盖目标文件，也不会触发配置重载。

## 版本内容

每个版本包含唯一版本 ID、创建时间、当前登录操作者、配置类型、目标文件、SHA-256 摘要、前一版本 ID 和动作名称。后台任务的操作者记为 `system`。

版本索引和内容位于主配置同级的 `.lywaf-config-history` 目录，最多保留 100 个版本。该目录可能包含密码、令牌等配置内容，部署时必须限制为服务账号可读写，不应由静态文件服务或反向代理暴露。

## 控制台操作

“配置文件”页面底部提供配置历史：

- **查看差异**：逐行展示新增、删除和未变内容；差异最多返回 5000 行。
- **回滚**：回滚前二次确认。系统不会改写旧版本，而是用历史内容创建新的回滚版本，然后重新加载。

## 管理 API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/config/history` | 按时间倒序查询版本 |
| `GET` | `/api/config/history/{id}/diff` | 查询该版本与前一版本的逐行差异 |
| `POST` | `/api/config/history/{id}/rollback` | 创建回滚版本、原子写入并重载 |

这些接口受控制台认证和控制端口限制保护。回滚操作同时写入审计日志。

## 原子性的边界

单个目标文件的替换是原子的，读取方不会观察到半份配置。版本索引、归档内容和目标配置是多个文件，因此不等同于数据库事务；异常中断后可依据内容摘要和归档文件人工核查。监听端口、进程级依赖注入和中间件结构也不会因普通配置重载自动重建。

## 验证

自动化测试覆盖有效版本写入、无效候选拒绝、旧配置保留和历史回滚：

```powershell
dotnet test tests/LyWaf.Tests/LyWaf.Tests.csproj --no-restore
```
