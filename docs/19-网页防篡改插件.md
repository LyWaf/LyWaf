# 网页防篡改插件

## 工作原理

网页防篡改是系统插件 `web-tamper`。它按“网站 + 路径”保存已确认响应内容及指纹。当上游内容改变时，LyWaf 记录变更事件，并继续向访客返回安全基线，直到管理员确认更新。

```text
请求 -> 匹配保护资源 -> 获取/检查上游 -> 指纹一致 -> 正常返回
                                  |
                                  +-> 指纹变化 -> 返回基线 + 生成待确认事件
```

## 网站维度

配置路由中的具体域名会自动发现，也可在插件页面手工添加域名和非标准端口。网站只保存 authority，例如 `example.com` 或 `localhost:8080`；检查时优先 HTTPS，失败后尝试 HTTP。同一域名不会因 scheme 不同建立两份网站记录。

配置发现的网站也可修改备注，但不能像手工网站一样从插件中删除，因为其来源仍是路由配置。

## 资源类型

- 精确路径：`/index.html`。
- 全站目录规则：`/*`。
- 子目录规则：`/static/*`。
- .NET catch-all 风格：`/static/{**match}` 或 `/static/{**match**}`。

精确路径在添加时抓取基线。目录规则不会把整个站点一次性抓取进内存，而是在实际请求经过 WAF 时收集匹配路径，每个实际路径维护独立基线。

## 惰性检查与远程访问控制

前端请求命中受保护路径后，路径会尝试加入后台检查队列。同一资源一分钟内已请求过时不会重复加入；超过一分钟才会再次后台访问远程端。并发请求仍受同一分钟缓存去重，避免持续拉取上游。

远程响应和本地基线都通过文件流和文件句柄处理，不会将所有文件一次性读入内存。远程抓取有大小和超时限制，避免异常响应造成短期内存压力。

## 排除、暂停与删除

- 排除子资源：目录规则继续生效，但指定实际路径不再受保护；排除项仍可手动检查。
- 暂停规则：暂时停用整个精确资源或目录规则。
- 删除子资源：删除其基线；如果仍匹配上级目录规则，下次请求会重新收集。
- 删除规则：删除规则及相关数据，操作前应确认不再需要历史基线。

## 检查和确认

点击“检查”时界面显示 Loading；超过请求超时会明确提示超时。发现变化后可查看：

1. Git 风格统一差异：红色删除、绿色新增、双行号。
2. 折叠上下文：每个折叠段可独立展开和收起。
3. 本地安全基线完整版。
4. 线上当前内容完整版。

“继续使用安全基线”不会信任上游变化；“确认正常，更新基线”会把当前上游内容设为新基线。相同资源的多条未确认事件按资源合并，只保留最新变化用于确认；再次检查发现已与基线一致时可自动消除过期待确认状态。

## 插件 API

控制台不直接暴露 `/api/web-tamper/...`。页面通过统一插件转发入口调用：

```text
/api/plugins/web-tamper/proxy/websites
/api/plugins/web-tamper/proxy/resources
/api/plugins/web-tamper/proxy/events
```

这样页面、API、中间件和生命周期都归插件所有。插件禁用后，其管理能力也应视为不可用。

## 数据与备份

运行数据位于程序输出目录的 `datas/web-tamper`。备份时应包含资源元数据、基线文件和事件数据，并保持文件之间的一致性。不要只备份 JSON 而遗漏基线内容。

## 使用建议

- 先保护入口 HTML、关键 JS/CSS 和支付回调说明页。
- 对变化频繁、用户个性化或包含时间戳的接口不要直接建立静态基线。
- `/*` 可能产生大量实际路径，应监控磁盘增长并合理排除动态 API。
- 确认变更前必须查看差异和线上完整内容，不要仅凭哈希变化更新。

## 目录规则生命周期

目录规则保存匹配模式，子资源在真实请求首次经过 WAF 时惰性出现。每条实际路径具有独立 Hash、检查时间、排除状态和基线。删除父规则前应明确是否删除已收集子资源。

## 差异与完整内容

差异视图可折叠长段相同内容，但折叠块必须能手动展开，并提供本地安全基线和线上当前内容完整视图。二进制或超大内容显示摘要、大小和下载入口，避免直接渲染耗尽浏览器内存。

## 故障与恢复验证

覆盖 HTTPS、HTTP 回退、非标准端口、上游 4xx/5xx、超时、大响应和磁盘不足。并发命中同一路径时一分钟内最多拉取一次远端，本地比较使用文件句柄。恢复备份后检查元数据、事件和基线文件一致。
