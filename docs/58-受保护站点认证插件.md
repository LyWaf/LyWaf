# 受保护站点认证插件

`site-auth` 是代理流量侧的系统插件，用于给指定域名和路径增加访问认证。它与控制台管理员认证使用不同的类型、端点、Cookie 名和签名密钥，不能互认会话。

## 策略

在 `Plugins.site-auth.Policies` 中按 `Host` 和 `Path` 配置策略。路径支持 `*` 匹配单段、`**` 匹配多段。`Mode` 可选 `Form`、`Basic` 或 `OAuth2`，`AllowedGroups` 限制用户组，`IpExceptions` 为精确 IP 恢复入口。

本地用户密码只接受以下 PBKDF2-SHA256 格式，迭代次数至少 100000：

```text
pbkdf2-sha256$迭代次数$Base64盐$Base64摘要
```

Form 登录签发 HttpOnly、SameSite=Lax 的独立 Cookie；HTTPS 请求同时设置 Secure。会话包含到期时间和用户组并由 `SessionSecret` HMAC 签名。Basic 模式不签发 Cookie。认证失败按客户端 IP 做一分钟窗口限速并写入审计日志。

## OAuth2

OAuth2 使用授权码流程。`AuthorizationEndpoint`、`TokenEndpoint`、`UserInfoEndpoint`、`ClientId`、`ClientSecret` 和 `RedirectUri` 必须完整配置，Token 和 UserInfo 端点只允许 HTTPS。回调 state 由站点认证独立密钥签名且五分钟过期，从 UserInfo 的 `UsernameClaim`、`GroupsClaim` 提取身份。

插件默认关闭。启用前需要在插件管理中批准 `Network` 和 `SensitiveConfiguration` 权限，并配置随机高熵的 `SessionSecret`。OAuth 客户端密钥和站点会话密钥不得使用控制台管理员密钥。

## 插件管理 API

管理 API 统一走 `/api/plugins/site-auth/proxy`，并要求插件获得 `ConsoleApi` 权限：

- `GET /config`：读取脱敏配置、策略和用户摘要。
- `PUT /settings`：更新 Cookie、会话时间、失败限速和可选新会话密钥。
- `POST /policies`、`PUT /policies/{id}`、`DELETE /policies/{id}`：管理域名/路径策略。
- `POST /users`、`PUT /users/{username}`、`DELETE /users/{username}`：管理本地用户。明文密码仅用于本次请求，后台立即转换为 PBKDF2-SHA256。
- `PUT /oauth2`：更新 OAuth2 端点和可选新客户端密钥。

GET 响应不会包含密码摘要、OAuth 客户端密钥或会话签名密钥。所有写操作经过版本化嵌套配置补丁、动态重载和审计，不需要重启进程。
