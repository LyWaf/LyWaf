# 部署

## 支持的部署形态

| 形态 | 用途 |
|---|---|
| 完整 WAF | 反向代理、路由、安全防护、统计和控制台 |
| 快速代理 | 使用 `proxy` 子命令临时转发单一上游 |
| 文件服务 | 使用 `file` 子命令或 `file_server` 站点 |
| Mock 响应 | 使用 `respond` 子命令或站点 `respond` |
| 正向代理 | HTTP、HTTPS、SOCKS5 和可选 PCAP |
| TCP Stream | 非 HTTP TCP 服务转发 |

生产部署应使用 `run -c config.ly` 并由操作系统服务管理，不建议把交互式终端当作守护程序。

## 运行要求

- .NET/ASP.NET Core Runtime 9，源码编译需要 .NET 9 SDK。
- Windows 或主流 Linux 发行版；其他平台需自行完成依赖与行为验证。
- 工作目录必须允许写入日志、DuckDB、插件数据和状态文件。
- ACME HTTP-01 需要公网 80 端口能够到达 LyWaf。

## 默认端口

| 端口 | 用途 | 建议 |
|---|---|---|
| 80/TCP | HTTP、ACME Challenge | 对公网开放或由外层 LB 转发 |
| 443/TCP | HTTPS | 对公网开放或由外层 LB 转发 |
| 7030/TCP | 控制台 | 默认只绑定 `127.0.0.1` |

正向代理和 Stream 端口完全由 `config.ly` 决定，应按最小权限单独开放。

## Linux systemd 示例

```ini
[Unit]
Description=LyWaf
After=network-online.target

[Service]
WorkingDirectory=/opt/lywaf
ExecStart=/usr/bin/dotnet /opt/lywaf/LyWaf.dll run -c /opt/lywaf/config.ly
Restart=on-failure
RestartSec=5
User=lywaf
Environment=DOTNET_ENVIRONMENT=Production

[Install]
WantedBy=multi-user.target
```

监听 80/443 时可使用 systemd capability 或外层端口转发，不要仅为绑定低端口让整个进程长期以 root 运行。

## Windows

发布目录放在固定路径，由 Windows Service 包装器或企业进程管理工具执行：

```text
dotnet.exe D:\LyWaf\LyWaf.dll run -c D:\LyWaf\config.ly
```

服务账号需要读取证书、写入数据目录和绑定配置端口的权限。更新前先优雅停止，避免 DuckDB 或基线文件写入中断。

完整步骤见 [从零搭建](15-从零搭建.md)，上线要求见 [生产上线检查清单](22-生产上线检查清单.md)。

## 反向代理与防火墙

若 LyWaf 前还有 CDN 或负载均衡器，应只信任其出口地址写入的真实客户端 IP 头，并限制源站只能由 LyWaf 访问。控制端口通过本机、VPN 或管理网访问，不与 80/443 一并开放。

多节点启用 `RuntimeState` 时，各节点必须使用唯一且稳定的 `NodeId`，并通过管理网或 mTLS 网络访问彼此控制端口。只开放 HMAC 保护的 agent 接口并不替代网络隔离；共享密钥应由环境变量或密钥系统注入。部署拓扑和一致性取舍见[分布式运行状态](36-分布式运行状态.md)。

## 升级步骤

1. 记录当前版本并备份配置、DuckDB、认证、证书和插件数据。
2. 在测试环境验证新版本配置解析和前端页面。
3. 优雅停止旧实例，确认没有数据库和基线写入。
4. 替换程序文件，保留数据目录并执行必要迁移。
5. 前台启动观察日志，再交回服务管理器。
6. 验证健康检查、业务请求、控制台和关键安全策略。

不要直接覆盖正在加载的外部插件 DLL。涉及前端插件、DI 注册或中间件结构的升级必须重启。

## 运行监控

至少监控进程存活、端口、请求错误率、上游健康、CPU、内存、句柄、磁盘空间、DuckDB 查询和证书有效期。日志轮转和数据保留必须在磁盘耗尽前生效。

## 回滚

保留上一版本程序和对应配置。新版本失败时停止实例、恢复程序与必要数据备份，再按旧版本启动；数据库或插件数据发生不可逆迁移时必须使用迁移前备份，不能只回滚二进制。
