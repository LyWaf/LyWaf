# 服务发现

LyWaf 服务发现把外部实例列表转换为 YARP `DestinationConfig`。路由和 Cluster 的负载均衡、健康检查、重试、熔断配置仍来自 `ReverseProxy`；发现层只替换指定 Cluster 的 `Destinations`。

## 工作流程

1. `DiscoveryCoordinator` 按 Provider 的刷新时间拉取候选实例；DNS 优先采用响应 TTL，其他 Provider 使用 `RefreshSeconds`。
2. Provider 返回统一的 `DiscoveredDestination` 列表。
3. 候选列表排序并计算 SHA-256 版本号。
4. 同一版本稳定达到 `DebounceMilliseconds` 后发布不可变快照。
5. `DiscoveryReloadSignal` 触发 YARP 重新加载。
6. `DiscoveryProxyConfigFilter` 只替换命中的 Cluster。

Provider 超时、格式错误、空结果或重复 Destination ID 时不会覆盖当前快照。删除 Provider 或关闭服务发现会移除动态快照，使 Cluster 恢复静态配置。

## File Provider

文件适合由脚本、配置中心 Sidecar 或编排系统原子生成。读取使用异步文件句柄和顺序扫描，并受 `MaxPayloadBytes` 限制。

```json
{
  "destinations": [
    {
      "id": "node-a",
      "address": "http://10.0.0.11:8080",
      "metadata": { "zone": "east" }
    }
  ]
}
```

Address 必须是 HTTP/HTTPS 绝对 URI。文件更新应先写临时文件，再原子重命名，避免读取半份 JSON。

## DNS Provider

`RecordType = "Address"` 直接向 `DnsServer` 查询 A/AAAA，以便读取权威 TTL，并可用 `IncludeIPv4/IncludeIPv6` 过滤地址。`localhost` 和 IP 字面值使用系统解析器。`RecordType = "SRV"` 查询服务记录，使用记录端口并保存 priority/weight 元数据。未配置 `DnsServer` 时选择活动网卡的 DNS，包括 Linux 常见的本机 stub resolver。

`DnsMinTtlSeconds` 和 `DnsMaxTtlSeconds` 限制 TTL 驱动的刷新区间，防止 TTL 为 0 导致忙轮询，也防止超长 TTL 让实例迟迟不更新。没有 TTL 的系统解析结果回退到 `RefreshSeconds`。当前查询使用 UDP；收到截断响应会视为本轮失败并保留旧地址，不会发布不完整记录。

DNS 结果转换为 IP Destination 后，地址变化会产生新快照；超时、NXDOMAIN、格式错误和空结果均保留旧地址。发现层只替换 Cluster 的 `Destinations`，不会写入 YARP 主动健康状态；主动健康检查、被动健康检查和异常驱逐仍由 Cluster 配置及对应策略独立处理。

## Docker Provider

Docker Provider 调用 Engine API 的 `/containers/json`，按 `Selector` 标签筛选运行中容器。Linux 推荐 `Endpoint = "unix:///var/run/docker.sock"`；也可使用受 TLS 或网络 ACL 保护的 HTTP API。必须配置容器内部 `Port`。

挂载 Docker socket 等同授予高权限，只应让可信 LyWaf 进程访问。Windows named pipe 当前未实现，可使用受保护的 Engine HTTP 端点或 File Provider。

## Kubernetes Provider

Kubernetes Provider读取 EndpointSlice，只发布 `conditions.ready != false` 的地址。`ResourceKind = "Service"` 直接使用 `Service`；`Ingress` 会解析 networking.k8s.io/v1 Ingress 后端；`GatewayApi` 会解析 gateway.networking.k8s.io/v1 HTTPRoute 的 Service backendRefs。后两种模式通过 `ResourceName` 指定入口资源。

`Port = 0` 使用 EndpointSlice 端口，非零值用于覆盖。集群内默认读取 ServiceAccount token 和 `ca.crt`，也可通过 `TokenFile/CaFile` 指定。

Ingress、Gateway API 和厂商 CRD 最终都将流量指向 Service，因此该 Provider 不重复解析入口规则，只发现 Service 后端实例。RBAC 只需授予目标命名空间 EndpointSlice 的 `get/list`。

## Consul 与 Nomad

当前没有内置 Consul/Nomad Provider。两者是否加入取决于真实部署需求：

- Consul 推荐读取健康服务 API，并把 blocking query index 映射为快照版本。
- Nomad 推荐读取 allocation/service registration，并只发布健康 allocation。
- 在需求出现前，可由 Consul Template/Nomad Template 原子生成 File Provider JSON，减少核心依赖和认证面。

## 状态与验证

鉴权后访问 `GET /api/v1/discovery/snapshots` 查看当前 Cluster、Provider、版本、观察时间和实例。自动测试覆盖文件边界、DNS A/AAAA、SRV 压缩记录、Docker 标签、Kubernetes ready 状态、YARP Cluster 替换及失败保留。
