# 负载均衡

LyWaf 提供 8+ 负载均衡算法，均实现为 YARP 的 ILoadBalancingPolicy：

| 算法 | 策略 | 适用场景 |
|------|------|----------|
| WeightedRoundRobin | 按权重循环分发 | 通用 |
| WeightedLeastConnections | 路由到最少连接的后端 | 负载不均 |
| IpHash | 按客户端 IP 哈希做会话粘连 | 会话保持 |
| GenericHash | 按 Cookie/Header/参数哈希 | 自定义亲和 |
| WeightedRandom | 带权重的随机选择 | 简单分发 |
| ConsistentHash | 一致性哈希环 | 缓存友好的扩缩容 |
| ABCookieTest | 按 A/B 测试 Cookie 路由 | 功能测试 |
| ABTestWeighted | 带权重的 A/B 流量分割 | 灰度发布 |

## 健康检查

- **ActiveHealth**：定期 HTTP 探针检测后端
- 后端不健康时自动故障转移
- 可配置探针间隔、超时和阈值
- 健康状态通过 API 和仪表板暴露

## 算法选择

无状态且实例能力接近时优先轮询；实例规格差异明显时配置权重；长请求场景可使用最少连接；需要会话亲和时选择 IP 或业务键哈希。一致性哈希减少扩缩容时的键迁移，但不能保证后端永久不变。

A/B 策略用于发布实验，不等同于高可用负载均衡。实验 Cookie、权重和默认组必须有回退值，并验证未携带 Cookie 的首次请求。

## 目标与健康状态

主动健康检查失败的目标会退出可用集合。探针路径应轻量但能验证关键依赖，不能只返回固定 200 掩盖数据库故障。间隔过短会增加上游压力，超时过长又会延迟故障摘除。

## 上线验证

1. 分别直连每个上游确认响应。
2. 经 LyWaf 连续请求，观察分布是否符合策略。
3. 停止一个上游，确认在健康阈值后被摘除。
4. 恢复上游，确认达到恢复条件后重新加入。
5. 检查无可用目标时的状态码和日志。

排查分布异常时同时检查权重、健康状态、会话键和客户端真实 IP。使用 IP Hash 时，若所有请求都来自同一层代理，必须先正确恢复真实客户端 IP。
