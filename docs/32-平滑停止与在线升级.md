# 平滑停止与在线升级

本章记录 LyWaf 当前已经实现的平滑停止协议，以及在线升级仍需满足的进程交接条件。不能把“进程自动重启”当作“零中断在线升级”。

## 已实现的排空流程

调用控制台重启接口后，实例按以下顺序执行：

1. 将就绪状态切换为 `false`，通知负载均衡器停止分配新流量；
2. 新进入代理管线的请求返回 `503 Service Unavailable` 和 `Retry-After: 5`；
3. 等待已进入管线的 HTTP 请求、文件下载和 WebSocket 连接结束；
4. 达到 `Lifecycle:DrainTimeoutSeconds` 后仍未排空则记录剩余数量并继续停止；
5. 停止插件、网页防篡改队列、代理服务及其他托管后台服务；
6. `StatisticFlushService.StopAsync` 在周期线程结束后执行最终 DuckDB 刷写和 checkpoint；
7. DI 容器最后释放 DuckDB，应用停止后再清理共享内存状态。

配置示例：

```ly
Lifecycle {
    DrainTimeoutSeconds = 30
    ShutdownTimeoutSeconds = 15
}
```

## 健康与状态接口

| 方法 | 路径 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/health/ready` | 无 | 就绪返回 200，排空或未就绪返回 503 |
| `GET` | `/api/lifecycle/drain` | 控制台认证 | 查看在途请求、WebSocket 和排空开始时间 |
| `POST` | `/api/restart` | 系统管理权限及二次验证 | 启动排空，完成或超时后重建应用 |

`/api/health/ready` 只应通过控制监听端口暴露给本机代理、编排器或受信任的管理网络。

## 在线升级交接流程

LyWaf 使用候选探针和版本指针完成以下交接：

1. 运维人员将 ZIP 放入 `Lifecycle:Upgrade:InboxDirectory`，控制台只提交文件名、版本号和 SHA-256。
2. 服务流式计算摘要，限制压缩包大小、条目数和实际解压字节，拒绝绝对路径、目录逃逸、符号链接和重复路径。
3. 候选包解压到不可变版本目录，并执行候选程序自己的 `validate --config`。
4. 激活前，候选程序在自动分配的回环端口启动；DuckDB、插件、ACME、HTTP 代理和 TCP 代理在探针进程中禁用。
5. 候选 readiness 返回 200 后，旧实例才进入摘流和请求排空。
6. 旧实例释放生产监听后终止探针，以同一候选版本和真实配置启动生产进程。
7. 生产候选在限制时间内就绪后提交 `current/previous` 指针；失败则清除 pending 并由仍存活的旧进程重新构建旧应用。

程序指针位于版本仓库的 `pointers.json`，配置版本独立保存在 `.lywaf-config-history`。程序回退同样先启动上一入口点的隔离探针，成功后才摘流。

## 升级配置

```ly
Lifecycle {
    Upgrade {
        InboxDirectory = "upgrades/inbox"
        ReleaseDirectory = "upgrades/releases"
        MaxPackageBytes = 536870912
        MaxExtractedBytes = 1073741824
        MaxEntries = 20000
        ValidationTimeoutSeconds = 30
        ReadinessTimeoutSeconds = 30
    }
}
```

版本号只允许字母、数字、点、下划线和短横线。已存在版本目录不可覆盖。

## 升级 API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/upgrade/releases` | 查询候选版本及 current/previous/pending 指针 |
| `POST` | `/api/upgrade/stage` | 按收件箱文件名、版本和 SHA-256 校验入库 |
| `POST` | `/api/upgrade/activate` | 隔离探针通过后激活候选版本 |
| `POST` | `/api/upgrade/rollback` | 隔离探针通过后回退上一版本 |

入库、激活和回退均记录控制台操作者审计日志。控制台“配置文件”页面提供对应版本管理区域。

## Windows 与 Linux

- Linux 可结合 systemd、容器编排器或外部代理把临时候选加入流量入口，实现双实例滚动更新；systemd socket activation 仍需要额外的 Kestrel 句柄接入代码。
- Windows 不假设支持 Unix 文件描述符继承，使用隔离回环端口验证候选，再串行释放和绑定生产端口。
- 单机且没有外部流量入口时，生产端口从旧 Kestrel 释放到新 Kestrel 绑定之间仍可能有极短窗口；协议保证已有请求排空和失败恢复，但不虚假承诺网络层绝对零丢包。

## 验证

测试覆盖排空等待、新请求拒绝、HTTP/WebSocket 计数、超时退出、ZIP 路径逃逸、版本指针提交/回退/abort，以及真实候选进程的隔离 readiness。运行：

```powershell
dotnet test tests/LyWaf.Tests/LyWaf.Tests.csproj --no-restore
```
