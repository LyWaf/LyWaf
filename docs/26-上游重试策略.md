# 上游重试策略

上游重试用于处理短暂的网络错误和 `502`、`503`、`504` 等可恢复响应。重试会放大上游流量，因此默认关闭，且默认方法仅包含 `GET`、`HEAD` 和 `OPTIONS`。

## Cluster 级配置

在站点或路径的代理配置中增加 `retry` 块。策略应用于该配置生成的上游 Cluster。

```ly
api.example.com {
    proxy = ["http://10.0.0.11:8080", "http://10.0.0.12:8080"]

    retry {
        Enabled = true
        MaxAttempts = 3
        Methods = ["GET", "HEAD", "OPTIONS"]
        StatusCodes = [502, 503, 504]
        RetryNetworkErrors = true
        PerTryTimeoutMs = 2000
        TotalTimeoutMs = 6000
        BaseBackoffMs = 100
        MaxBackoffMs = 1000
        BudgetPercent = 20
        BudgetMinRetriesPerSecond = 1
    }
}
```

`MaxAttempts` 包含第一次请求。上述配置最多产生一次初始请求和两次重试。退避按 `BaseBackoffMs` 指数增长，并受 `MaxBackoffMs` 限制。

## Route 级覆盖

路径内的策略会覆盖站点级策略，适合只对读接口启用重试。

```ly
api.example.com {
    /v1/query/* {
        proxy = ["http://127.0.0.1:8101"]
        retry {
            Enabled = true
            MaxAttempts = 2
            PerTryTimeoutMs = 1000
            TotalTimeoutMs = 2500
        }
    }

    proxy = ["http://127.0.0.1:8100"]
}
```

未填写的字段使用安全默认值。策略值具有边界限制，避免错误配置产生无限重试或无限等待。

## 请求安全边界

- 默认只重试幂等、安全方法。
- 即使显式加入 `POST`、`PUT` 等方法，当前实现也只重试无请求体的请求，避免无法可靠重放流式或大体积请求体。
- 客户端取消会立即停止，不会作为网络错误重试。
- `PerTryTimeoutMs` 限制单次上游访问；`TotalTimeoutMs` 覆盖所有尝试与退避等待。
- Retry Budget 按 Cluster 统计最近十秒流量，将额外重试限制为请求量的一定比例，并可设置每秒最低额度。

## 指标与排障

Prometheus 指标 `lywaf_upstream_retry_attempts_total` 包含 `cluster`、`destination`、`outcome` 和 `attempt` 标签。常见结果包括：

| outcome | 含义 |
|---|---|
| `status_503` | 本次收到可重试状态并将继续尝试 |
| `try_timeout` | 单次尝试超时 |
| `total_timeout` | 整体请求时间耗尽 |
| `network_error` | 连接或传输失败 |
| `budget_exhausted` | Retry Budget 拒绝额外尝试 |
| `exhausted_status_503` | 最后一次尝试仍返回可重试状态 |
| `completed` | 重试后取得非重试响应 |

不要把未经约束的原始 URL Path 放入指标标签。当前目标标签只记录有限长度的上游 authority，避免 API 路径造成高基数。

## 上线建议

先对只读接口启用两次尝试，观察上游并发、延迟和 `budget_exhausted`。总超时必须小于外层代理或客户端超时；否则客户端已经断开时，后台重试没有实际价值。持续性故障应由健康检查、熔断和异常实例驱逐处理，而不是增加重试次数。
