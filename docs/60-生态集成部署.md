# 生态集成部署

LyWaf 的生态边界是 HTTP 反向代理、YARP 路由元数据、Kubernetes 服务发现、外部授权协议和插件 SDK，不要求第三方系统链接 LyWaf 内部程序集。

## Kubernetes

`Services/Discovery/KubernetesDiscoveryProvider` 使用 ServiceAccount Token 和 Kubernetes API 发现服务端点，Token 不写入日志。LyWaf 可作为 Deployment/DaemonSet 部署，由 Service 暴露代理端口；Ingress 或 Gateway API 控制器继续负责入口地址时，把 LyWaf 配置为后端网关即可。

当前不直接实现 Kubernetes Gateway API Controller：控制器需要 CRD watch、status 回写、leader election、RBAC 和一致性测试，这与 LyWaf 单进程网关职责不同。生产环境应由成熟控制器管理 Gateway API，再将流量转给 LyWaf；服务发现仍由 LyWaf 负责。

## Kong 与 Envoy

有三种组合：

| 模式 | 数据流 | 适用场景 |
|---|---|---|
| LyWaf 在前 | 客户端 -> LyWaf -> Kong/Envoy | 使用 LyWaf WAF、缓存和插件，后层负责服务治理 |
| LyWaf 在后 | 客户端 -> Kong/Envoy -> LyWaf -> 应用 | 前层统一入口、TLS/JA4，LyWaf 做应用安全 |
| 独立检测 | 网关 -> LyWaf 外部授权兼容服务 | 只复用判定服务，不串联完整代理 |

Envoy 或支持 JA4 的 TLS 终止层可把 JA4 写入配置的 Header，但 LyWaf 只信任 `TrustedFingerprintProxies` 中的直连地址。Kong/Envoy 的认证或检测插件也可作为 `ExternalAuthorization.Endpoint`，请求字段、Body 大小、超时、缓存和失败策略见《外部授权接口》。

## 插件 SDK

LyWaf 专属能力优先使用插件 SDK：插件声明权限、独立数据目录、迁移、后台任务、控制台 API 转发和页面入口。站点认证、网页防篡改属于系统插件；第三方检测器可实现 `IPluginApiHandler` 提供管理 API，并在代理管线中使用有界 DTO，不能长期持有 `HttpContext`。

## 验收

- Kubernetes API 不可用时保留最近发现结果并暴露错误，不清空所有上游。
- 外部授权超时遵守每路由 fail-open/fail-closed，且不会发送未列入白名单的凭据。
- JA4 Header 由非可信来源发送时忽略。
- 插件卸载或禁用后不保留中间件行为，插件数据和控制台会话相互隔离。
