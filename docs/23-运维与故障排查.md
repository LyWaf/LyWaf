# 运维与故障排查

## 日常操作

```powershell
dotnet LyWaf.dll run -c config.ly
dotnet LyWaf.dll start -c config.ly
dotnet LyWaf.dll reload -c config.ly
dotnet LyWaf.dll stop -c config.ly
dotnet LyWaf.dll reset password
```

涉及监听端口、Kestrel、启动期服务或插件注册的配置，优先完整重启。普通路由和 Options 配置可先尝试重载，并从日志确认是否成功应用。

## 必须持久化的内容

| 路径/文件 | 内容 |
|---|---|
| `config.ly` 和拆分配置 | 主配置 |
| `certs` | 手工证书和私钥 |
| `datas` | DuckDB 统计数据等 |
| `datas/ip-groups.json` | IP 组 |
| `datas/web-tamper` | 防篡改基线、资源和事件 |
| `plugin_data` | 通用插件状态和插件自有数据 |
| `.lywaf.*` | 认证、规则或草稿等运行状态 |
| 防篡改数据目录 | 基线、资源元数据和事件 |

备份前应尽量优雅停止或执行数据库检查点，避免只复制一半更新。恢复时保持原工作目录结构和文件权限。

## 启动慢

按启动耗时日志定位阶段。DuckDB 建立连接慢时检查：

- 数据库和 WAL 大小、磁盘延迟、杀毒软件扫描。
- 上次是否被强制结束，导致恢复或检查点耗时。
- 数据保留和刷写频率是否合理。
- 数据目录是否位于网络盘或低速盘。

不要通过删除数据库直接解决启动慢，除非已经确认不需要历史数据并完成备份。

## 502/504

1. 从 LyWaf 主机直接请求上游。
2. 检查协议、地址、端口和 DNS。
3. 检查健康检查是否将全部节点标记异常。
4. 检查连接数、超时和 TLS 信任。
5. 用请求 ID 对齐访问日志与上游日志。

## 路由不匹配

- 用 `Host` 头测试，不要只访问 IP。
- 核对端口是否包含在站点 Host 中。
- 检查更具体路径是否覆盖默认路由。
- 检查 Method 限制；CORS 预检需启用 Cors 配置。
- 查看生成路由和控制台路由配置页面。

## 防护误报

先把规则切换为观察模式或临时停用，不要删除全部规则。保存命中请求的 Path、Method、Header、Body 特征和规则 ID，再收窄字段、操作符或作用路径。

## 网页防篡改异常

| 现象 | 处理 |
|---|---|
| `/*` 未收集路径 | 请求必须实际经过 LyWaf，并匹配网站 authority |
| 检查缓慢 | 等待 Loading；检查上游、TLS 和超时 |
| 一直待确认 | 再次检查状态；一致时应清理旧状态，变化时查看差异后确认 |
| 基线数量增长过快 | 排除动态 API，缩小目录规则，监控磁盘 |
| 非标准端口失败 | 网站使用 `domain:port`，不要填写 scheme |

## 构建文件被占用

Windows 上运行中的 LyWaf 会锁定 `bin/.../LyWaf.dll`。验证编译可先停止实例，或输出到独立目录：

```powershell
dotnet build --no-restore -p:OutDir=D:\temp\lywaf-build\
```

## 回滚

1. 保留上一版本发布目录和配置快照。
2. 优雅停止当前实例。
3. 恢复程序与兼容的配置，不覆盖更新后的运行数据。
4. 启动并执行健康检查。
5. 如果新版本修改了数据格式，按迁移说明恢复对应数据备份。

程序回滚和数据回滚应分开决策，避免旧程序读取不兼容的新格式。

## 资源异常

内存增长按响应缓冲、深度日志、高基数路径、后台队列和 DuckDB 查询排查；句柄增长检查临时文件、基线、网络响应和订阅；磁盘增长分别统计日志、数据库、抓包、插件数据和临时目录。先保留现场指标和最近变更，不直接删除未知数据。

## 插件故障

依次检查发现、状态、初始化和启动日志，再看统一 API 的 503/404。禁用后确认中间件旁路；新增 DLL、DI 或管线需重启。后台拉取检查一分钟去重、队列、超时和响应上限。

## 事件记录模板

记录发现时间、影响范围、状态码、版本、最近变更、关键日志、临时处置、根因、永久修复和验证结果。复盘后把新检查项加入上线清单。
