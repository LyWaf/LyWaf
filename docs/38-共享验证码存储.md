# 无数据库的跨节点验证码

用户于2026-10-20要求不启用Redis、不引入第三方数据库，保持轻量。当前实现将验证码的签发与消费统一交给一个指定的 LyWaf 节点，直接使用本地文件、递增序号和现有签名HTTP通信；无需部署独立存储服务。

时间戳负责新鲜度，递增序号负责持久顺序。两个节点可能同时持有相同时间或状态，因此单靠时间排序不能保证一次性。权威节点串行检查挑战，先刷盘序号，再原子发布不含答案的已消费记录，最后才返回答案用于验证。普通请求仍走本地代理路径，只有挑战交互需要访问权威节点。

## 本地配置

假设控制节点ID为 `controller`、集群ID为 `production`，在所有节点本地 `config.ly` 配置：

```text
CaptchaStore {
    Provider = "Authority"
    ClusterId = "production"
    AuthorityNodeId = "controller"
    AuthorityEndpoint = "https://10.0.0.10:7030"
    StateDirectory = ".lywaf-captcha"
    TimeoutMilliseconds = 2000
    MaxChallenges = 10000
    MaxBytes = 67108864
}
```

| 字段 | 含义 |
| --- | --- |
| Provider | 单机默认 `Local`；跨节点使用内置 `Authority`；不再支持 Redis |
| ClusterId | 与 NodeCommunication.ClusterId 一致的集群标识 |
| AuthorityNodeId | 唯一负责挑战写入和消费的 LyWaf NodeId |
| AuthorityEndpoint | 该节点控制API地址；远程节点必需，HTTPS要求跟随 NodeCommunication.RequireHttps |
| StateDirectory | 权威节点的私有本地持久目录，不放在静态网站目录、异步同步目录或网络共享卷中；普通节点不创建此目录 |
| TimeoutMilliseconds | 排队/远程请求等待上限，100–10000毫秒，默认2000；写入刷盘期间不截断正在提交的记录 |
| MaxChallenges | 未到期的签发及已消费记录总数上限，默认10000、最大100000；已消费记录保留至到期以阻止再次签发同token |
| MaxBytes | 文件正文预算，默认64MiB，范围16KiB–512MiB；替换临时副本也预留空间 |

启用 NodeCommunication 或 RuntimeState 的多节点实例需要 Authority；其中 NodeCommunication 必须启用以提供签名通信。单机 Local 没有新增依赖。配置在启动时固定，修改后重启。远程业务配置分发保留节点本地的 CaptchaStore 配置。

## 节点权限

复用既有 NodeCommunication 的逐节点HMAC密钥、nonce持久防重放、时间窗和HTTPS。新增操作：

```text
captcha.store.issue
captcha.store.take
```

权威节点为每个允许验证的边缘节点显式登记这两个 AllowedOperations；边缘节点的权威Peer也显式登记这两个操作及对应密钥。密钥沿用已有逐节点配置，不增加验证码数据库密码。例如权威节点中：

```text
NodeCommunication {
    Enabled = true
    ClusterId = "production"
    NodeId = "controller"
    Role = "Controller"
    Peers {
        edge01 {
            Role = "Node"
            ActiveKeyId = "current"
            Keys { current = "${EDGE01_NODE_SECRET}" }
            AllowedOperations = ["captcha.store.issue", "captcha.store.take"]
        }
    }
}
```

边缘节点将NodeId设为自身，Peer名称改为 `controller`、Role改为 `Controller`，使用相应配对密钥。此例只展示新增操作；需要其他通信能力时保留已有权限。权威节点上的本地验证码直接调用同一个持久存储，不发回环HTTP。运行 AntiBot Challenge 模式时，所有验证节点还需相同的 `AntiBot.Secret`（至少32 UTF-8字节）及工作量难度。

## 顺序、重启及故障

- 权威目录持有独占 `.owner` 句柄；同目录第二个宿主不能接管写入。`sequence`保存集群、权威身份及持久高水位，重启后不复用序号；崩溃产生序号空洞是允许的。
- 每个挑战一份JSON记录，包含权威时间、到期时间、序号及答案。消费时记录的答案改为null并刷盘后发布。重复请求只读到已消费状态，原消息即使换nonce也不能再次取得答案。
- 算术/滑块有效期5分钟；AntiBot工作量证明为30–600秒。客户端时间只参与有界新鲜度检查，到期时间以权威节点接受时的时钟为准。
- 签发方在成功持久化后才给浏览器token；验证方在成功消费并校验答案/行为/作用域后才放行。CC仍需已有的签名release确认。会话token按设计可复用，不属于一次性挑战。
- 权威失联、超时、容量满或磁盘写失败时返回503，不回退到各节点独立消费；响应丢失或取消后重新获取挑战。不重试可能已经消费的取答案操作。
- 存储IO或损坏后当前实例停止继续处理，需要重启按持久文件恢复。恢复时允许高水位领先记录、清理未提交临时文件；缺失/倒退的高水位、身份不符或损坏记录失败关闭。
- 状态目录必须专用，不能使用文件系统根目录；发现无关文件时拒绝初始化，不删除无关临时文件。只有具备持久高水位的本服务临时记录可以按恢复协议清理。
- 同时排队最多256个请求，排队等待有界。容量满不会删除尚有效的已消费记录；正常请求会分批清理到期文件。文件内容预算不是整个进程RSS或文件系统块分配的硬限制。
- 不允许将目录回滚到旧备份后直接继续使用旧token。恢复旧备份时，停掉相关挑战交互并使用全新的状态目录/命名空间，旧挑战作废。权威不可用期间普通代理请求不依赖该存储，但必须验证的用户暂时无法完成挑战。

这保持单权威、轻量部署；不包含多权威选主、网络分区下继续消费或机器掉电的全文件系统证明。扩展为HA需要额外一致性协议，不能用各节点时间戳比较替代。

## 验证

```powershell
dotnet test tests/LyWaf.Tests/LyWaf.Tests.csproj -c Release --filter "FullyQualifiedName~FileCaptchaAuthorityTests|FullyQualifiedName~SharedCaptchaTests|FullyQualifiedName~NodeOperationContractHttpTests"
dotnet run --project benchmarks/CaptchaProcessHarness/CaptchaProcessHarness.csproj -c Release
```

进程工具只启动三个独立的LyWaf进程及临时目录，使用随机测试密钥，覆盖跨节点验证、验证码96路和证明48路并发、权威强杀/重启、失联关闭、未消费恢复及持久序号递增；不需要WSL、Redis或数据库。测试父进程仅读自己的fixture答案文件，不提供生产调试接口。最终后端1607/1607、前端49/49及类型检查通过，详见[节点通信最终说明](node-communication-final-verification-2026-10-20.md)。
