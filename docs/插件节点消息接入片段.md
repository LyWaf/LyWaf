# 插件节点消息接入片段

插件节点通信统一通过控制端口。宿主负责节点认证、防重放、准入、插件权限和消息版本分发；业务校验以及需要的中转行为由插件注册的处理器负责。

## 请求与响应

`plugin.request` 用于需要业务返回值的 RPC，不使用投递 ACK 代替查询结果。线上的载荷为 `PluginNodeRequestPayload(PluginId, MessageType, SchemaVersion, Data)`，外层沿用 v2 节点签名和稳定消息 ID。SDK 提供不依赖宿主程序集的 `PluginNodeRequest`、`PluginNodeResponse`、`IPluginNodeRequestHandler` 和 `IPluginNodeRequestClient`。

插件在 `PluginMetadata.NodeRequests` 声明消息类型和精确 schema，并声明 `PluginPermission.NodeMessaging`；在自己的 `ConfigureServices` 中注册 `IPluginNodeRequestHandler`。宿主只调用唯一匹配的运行中、已授权插件，缺插件返回 404，权限不允许返回 403，缺少唯一 schema 返回 422。旧操作名可由插件声明 `LegacyOperation`，兼容入口也走同样的插件生命周期和权限校验。插件不能覆盖宿主保留操作。

发送使用 `context.NodeRequests.RequestAsync(targetNodeId, messageType, schemaVersion, data, messageId, token)`。客户端固定绑定当前插件 ID，目标只能是宿主已授权的节点，不接受任意地址或密钥。节点模式只允许向中控发送；中转请求由插件自己的协议声明目标和业务约束，中控通过同一插件处理器处理，再复用既有 WebSocket 向目标发送。不会自动建立节点直连或在长连接失败后降级 HTTP。兼容模式仍遵循原有传输策略。

请求与回复限制为 256 KiB；SDK 请求总时限 5 秒，不自动重试。接收仍受节点消息大小上限约束。SDK 客户端在完成后重新检查插件权限、目标和密钥，避免配置变更恢复过期结果。请求 handler 接收的是宿主认证后的来源，不信任 `Data` 中自称的节点身份。需要重复提交的写操作由插件使用稳定业务消息 ID 实现持久幂等，不得把一次传输 ACK 当成业务完成证明。

流量分析插件通过 `AnalysisNodeRequests` 注册 CC 查询、中转查询和验证码解封请求。新托管请求使用 `plugin.request`；旧 `cc.execution.query`、`cc.execution.relay`、`cc.captcha.release` 只是插件声明的兼容别名，不再是宿主内置操作。宿主不解析 CC 策略、计数、封禁或签名证据。保护组隔离、挑战消费、证据绑定和封禁决策仍由插件业务处理验证，不因通道统一而删除。

`NodeProtocolOperations.All` 只列宿主操作和通用插件操作；插件别名通过注册声明参与路由和配置校验。新插件不需要编辑该列表或 `NodeCommunicationEndpoints`。启用新请求协议前，应将中控和节点一并更新；不支持的操作失败关闭，不回退到无认证通道。

## 投递与 ACK

`plugin.message` 和 `plugin.relay` 已在共享路由中注册，分别用于投递和中控中转。业务插件在 `PluginMetadata.NodeMessages` 声明类型、版本和目标组，并实现 `IPluginNodeMessageHandler`。发送使用 `context.NodeMessages`，无需修改宿主路由。

宿主的 `HandleAuthenticatedAsync` 只接收一次完整认证后的信封，不能在分发时再次调用 `ReceiveAsync` 验签，否则相同 nonce 会被防重放拒绝。独立宿主可单独映射 `ReceiveAsync`，但不能与共享路由重复映射。

## DI与准入

`AddLyWafPlugins` 已调用 `AddPluginNodeMessaging(configuration)`，注册 ACK 与 RPC 客户端及禁重定向的 `node-plugin-messages` HttpClient。ACK 通道还要求 `PluginNodeMessageOptions` 显式启用并授权目标组；RPC 通道使用运行中插件的精确请求声明和节点的 `plugin.request` 授权。使用独立协议宿主时必须自行注册处理器；没有插件生命周期管理器的精简宿主仅应注册其明确信任的处理器。

发送与接收均调用NodeAdmissionPolicy.Allows(peer, Operation)，Draining/Revoked/PendingApproval拒绝新插件消息。发送还要求Distribution.Nodes中的v2目标、明确AllowedOperations及密钥配置；实际发出前重新检查准入、权限、组成员和目标/密钥快照，变化则拒绝。

## 错误码

以下错误码已有双语资源；MessageKey 沿用 `node.errors.<code>`：

| Code | HTTP | 含义 |
| --- | --- | --- |
| node_plugin_forbidden | 403 | 插件能力、权限、目标组、发送者或节点准入不允许 |
| node_plugin_invalid_payload | 400 | 类型/组/版本/JSON对象、深度或字节上限不满足 |
| node_plugin_rate_limited | 429 | 速率、并发或速率索引容量已满 |
| node_plugin_message_conflict | 409 | 同一业务MessageId内容冲突 |
| node_plugin_outcome_unknown | 409 | 先前执行结果未知，禁止自动重复调用 |
| node_plugin_missing | 404 | 未安装、未运行或缺少接收handler |
| node_plugin_schema_unsupported | 422 | 没有唯一匹配的消息类型/schema版本声明 |
| node_plugin_store_unavailable | 503 | 审计/幂等存储满、忙、损坏或不可写 |

认证失败沿用既有node_*错误；消息在执行前到期沿用node_message_expired。插件明确业务NACK通过200 PluginNodeMessageReply(Ack=false, ErrorCode=插件稳定码)返回，文案由插件资源解释。远端HTTP失败不自动重试。

## 验证入口

`PluginNodeMessageTests` 覆盖 ACK 通道的签名、防重放、业务幂等、权限和组、额度、取消与存储故障。`PluginNodeRequestTests` 使用非 CC 示例插件验证 RPC 通用分发、认证来源、版本、停用、权限、兼容别名及绑定 SDK 客户端。`ManagedRuntimeHubTests` 和真实三实例验收覆盖 CC 查询、中转、解封、共享计数与封禁，确保业务安全约束不退化。
