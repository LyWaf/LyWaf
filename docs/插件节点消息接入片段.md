# 插件节点消息接入片段

主线程已完成以下共享节点路由接入。真实Kestrel HTTP测试通过正式DI注册和MapNodeCommunication验证成功、缺插件404及schema不兼容422；本代理没有修改NodeCommunicationEndpoints、NodeProtocolOperations或RuntimeState sync。

## 操作注册

在`Services/NodeCommunication/NodeProtocolOperations.cs`的All集合加入：

```csharp
PluginNodeMessageService.Operation, // "plugin.message"
```

此步骤也使NodeCommunication.Peers.AllowedOperations配置校验接受新操作。不要注册任意plugin.*路径或放宽未知operation校验。

## 共享接收路由

在`NodeCommunicationEndpoints`现有认证成功之后、默认configuration分支之前加入：

```csharp
if (name == PluginNodeMessageService.Operation)
{
    var result = await context.RequestServices
        .GetRequiredService<PluginNodeMessageService>()
        .HandleAuthenticatedAsync(message!, context.RequestAborted);
    return result.Error is { } rejected
        ? NodeProtocolResponse.Error(context, rejected)
        : Results.Json(result.Reply);
}
```

`HandleAuthenticatedAsync`是宿主程序集internal入口，不向SDK暴露。只能传入现有NodeMessageAuthentication.ReadAsync验证成功的信封。不能在此处调用ReceiveAsync再次验签，否则同一nonce会被防重放拒绝。独立宿主或测试可单独映射ReceiveAsync，它内部完成一次完整认证，但不要与共享路由重复映射。

## DI与准入

`AddLyWafPlugins`已经调用`AddPluginNodeMessaging(configuration)`，注册独立PluginNodeMessageOptions、服务和禁重定向的node-plugin-messages HttpClient。默认关闭。使用独立插件测试宿主时也可以直接调用该注册方法，并提供IPluginManager。

发送与接收均调用NodeAdmissionPolicy.Allows(peer, Operation)，Draining/Revoked/PendingApproval拒绝新插件消息。发送还要求Distribution.Nodes中的v2目标、明确AllowedOperations及密钥配置；实际发出前重新检查准入、权限、组成员和目标/密钥快照，变化则拒绝。

## 错误码

请主线程为以下8个新错误码补双语资源；MessageKey沿用node.errors.<code>：

| Code | HTTP | 含义 |
| --- | --- | --- |
| node_plugin_forbidden | 403 | 插件能力、权限、目标组、发送者或节点准入不允许 |
| node_plugin_invalid_payload | 400 | 类型/组/版本/JSON对象、深度或字节上限不满足 |
| node_plugin_rate_limited | 429 | 速率、并发或速率索引容量已满 |
| node_plugin_message_conflict | 409 | 同一业务MessageId内容冲突 |
| node_plugin_outcome_unknown | 409 | 先前执行结果未知，禁止自动重复调用 |
| node_plugin_missing | 404 | 未安装、未运行或缺少接收handler |
| node_plugin_schema_unsupported | 422 | 没有唯一匹配的消息类型/schema版本声明 |
| node_plugin_store_unavailable | 503 | 审计/幂等存储满、忙、损坏或不可写 |

认证失败沿用既有node_*错误；消息在执行前到期沿用node_message_expired。插件明确业务NACK通过200 PluginNodeMessageReply(Ack=false, ErrorCode=插件稳定码)返回，文案由插件资源解释。远端HTTP失败不自动重试。
