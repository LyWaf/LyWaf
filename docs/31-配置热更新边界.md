# 配置热更新边界

LyWaf 将配置变化按运行时影响分为三类。控制台保存并重载后会返回 `changeImpact`，界面在存在进程级变化时提示重启。

## 立即生效

通过 `IOptionsMonitor`、配置变更令牌或每次请求读取配置的策略可以立即生效，主要包括：

- `Protect`：基础防护和 WAF 自定义规则；
- `SpeedLimit`、`AccessControl`：限速和访问控制；
- `Global`、`Statistic`、`FileGlobal`；
- `CustomDns` 等已实现配置变更监听的服务参数。

“立即生效”表示不重建监听器和中间件管线，不代表正在处理的请求会中途改用新参数。

## 重建路由快照

以下配置由 YARP 或对应配置源生成新的路由快照：

- `ReverseProxy` 的路由、集群、目标和负载均衡参数；
- `FileServer`、`SimpleRes` 和 `ABTest` 的路由映射。

旧请求继续使用取得的旧快照，新请求使用新快照，切换过程不需要停止监听。

## 需要重启

以下内容在 `WebApplicationBuilder`、Kestrel、依赖注入或遥测管线构建阶段确定：

- `WafInfos:Listens`：HTTP、HTTPS 和控制台监听端口；
- `Plugins:Directories`：插件发现目录及中间件结构；
- `OpenTelemetry`、`Metrics`：遥测提供器和导出管线；
- `DuckDb`：数据库实例及后台服务生命周期。

修改这些字段后配置仍会保存，控制台会明确提示重启。插件的启用状态可以动态变化，但新增 DLL、发现目录和中间件顺序仍需要重启。

## 重载后冒烟检查

每次由控制台写入并重载的配置会检查：

1. 所有监听端口均在 `1-65535` 范围内；
2. 每条 YARP 路由引用的集群真实存在；
3. WAF 规则字段和操作符是已知枚举；
4. `Regex` 操作符的表达式可在限制时间内编译。

检查失败时，系统自动将磁盘文件回滚到写入前的版本并重新加载，调用方收到明确的失败原因。该机制与配置提供器的旧快照保留共同避免无效配置替换当前运行状态。

## API 返回

`POST /api/reload` 和 `POST /api/config/file` 的重载响应包含：

```json
{
  "restartRequired": true,
  "changeImpact": {
    "immediate": ["Protect"],
    "routeRebuild": ["ReverseProxy"],
    "restartRequired": ["WafInfos:Listens"],
    "requiresRestart": true
  }
}
```

`portsChanged` 为兼容旧版前端暂时保留；新功能应以 `restartRequired` 和 `changeImpact` 为准。
