# 插件开发实战

## 适合插件化的功能

功能具有独立配置、独立页面、独立 API、代理中间件或后台任务时，应优先做成插件。核心控制台不应出现某个插件专属的硬编码 API。

## 最小插件

```csharp
public sealed class DemoPlugin : LyWafPluginBase
{
    public override PluginMetadata Metadata => new()
    {
        Id = "demo",
        Name = "Demo",
        Version = "1.0.0",
        Priority = PluginPriority.Normal,
        EnabledByDefault = false
    };

    public override void ConfigureServices(IServiceCollection services, IConfiguration configuration)
    {
        services.AddSingleton<DemoService>();
    }

    public override void ConfigureProxyPipeline(IApplicationBuilder proxyApp)
    {
        proxyApp.UseMiddleware<DemoMiddleware>();
    }
}
```

## 生命周期

1. 发现插件并读取 Metadata。
2. `ConfigureServices` 在容器构建前注册依赖。
3. `InitializeAsync` 获取插件上下文。
4. `StartAsync` 启动运行逻辑。
5. 请求按优先级进入插件中间件。
6. 应用关闭时调用 `StopAsync`。

安全拦截类插件使用 `Highest/High`，分析和改写类功能根据是否需要看到核心处理前后的请求选择优先级。不要仅为“更早执行”全部设为 Highest。

## 插件 API

实现 `IPluginApiHandler`：

```csharp
public Task<IResult> HandleApiAsync(string path, HttpContext context)
{
    if (context.Request.Method == HttpMethods.Get && path.Trim('/') == "status")
        return Task.FromResult(Results.Json(new { success = true }));
    return Task.FromResult(Results.NotFound());
}
```

控制台统一入口为：

```text
/api/plugins/{pluginId}/proxy/{pluginPath}
```

前端应使用 `pluginProxyApi(pluginId)`，不要新增 `/api/demo/...` 这类核心接口。

## 插件页面

前端插件目录建议：

```text
Frontend/src/plugins/demo/
├── plugin.ts
├── api.ts
└── DemoPage.vue
```

`plugin.ts` 声明路由，`Frontend/src/plugins/index.ts` 会自动发现插件页面。后端 `GetActions()` 可返回 `page-link`，插件管理页据此显示“管理”入口。

## 配置

插件可通过 `DefaultOptions` 绑定 `Plugins:{id}`。`config.ly` 中使用：

```ly
Plugins {
    PluginConfigs {
        demo {
            Enabled = true
            SampleOption = "value"
        }
    }
}
```

具体键名以插件 Options 类型为准。系统插件是否允许关闭，应结合其依赖关系和业务影响决定。

## 数据和资源限制

- 数据写入插件数据目录，不要散落在程序根目录。
- 大响应使用流和临时文件，不使用无界 `MemoryStream`。
- 后台队列应有容量、去重、超时和取消机制。
- 网络拉取应缓存并限制频率、大小和并发。
- 插件停用或卸载时释放订阅、句柄和后台任务。

## 测试清单

- 启用、禁用、重启后的状态正确。
- API 只能通过统一插件代理访问。
- 页面刷新后路由仍可恢复。
- 插件异常不导致主代理失效。
- 并发、超时、大响应和磁盘不足均有受控行为。
- 配置热更新与需要重启的选项边界明确。

## 推荐开发顺序

先让元数据出现在管理页，再加入 Options 和只读状态 API，然后接入最小前端页面。中间件与后台队列最后加入，每一步保持可编译、可启动和可验证。

## 运行时与发布边界

禁用插件会停止生命周期，但已构建管线不会重新组合。中间件必须动态旁路；新增服务、管线、DLL 或页面后重启。发布包应说明兼容版本、配置、依赖、数据迁移和回滚，插件 ID 发布后保持稳定。
