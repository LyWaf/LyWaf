# 异常实例自动驱逐

Outlier Detection 根据真实代理请求的结果识别异常上游，并临时将其从负载均衡候选列表中移除。它适合发现“端口仍可连接但业务持续 5xx”或“少数实例连接失败”等主动探测不容易覆盖的问题。

## 配置

```ly
api.example.com {
    proxy {
        to = ["http://10.0.0.11:8080", "http://10.0.0.12:8080"]
        lb_policy = "RoundRobin"
        outlier_detection {
            Enabled = true
            ConsecutiveFailures = 5
            Consecutive5xx = 5
            WindowSize = 100
            MinimumVolume = 20
            ErrorRatePercent = 50
            EjectionDurationMs = 30000
            MaxEjectionPercent = 50
        }
    }
}
```

配置键支持 PascalCase、snake_case 和 kebab-case。

## 判定方法

- `ConsecutiveFailures`：连续转发错误阈值，包括连接、TLS、超时和传输错误。
- `Consecutive5xx`：目标连续返回 5xx 的阈值；其他目标的结果不会打断该目标的计数。
- `WindowSize`：每个目标保留的最近请求数，使用固定大小环形数组，内存不会随流量增长。
- `MinimumVolume`：达到该样本量后才启用错误率判断。
- `ErrorRatePercent`：滑动窗口失败比例阈值。

任一条件满足即可驱逐。驱逐时会清空该目标的旧统计；恢复后必须重新积累失败，避免历史窗口导致立即二次驱逐。

## 驱逐与恢复

`EjectionDurationMs` 决定目标保持 Passive Unhealthy 的时间。到期后 YARP 自动将 Passive 状态恢复为 Unknown，使目标重新进入候选列表。`MaxEjectionPercent` 限制一个 Cluster 同时可驱逐的目标比例，避免所有实例一起退出服务。

异常驱逐只写入 `DestinationHealthState.Passive`。主动健康检查继续独立维护 Active 状态，两个来源不会互相覆盖；最终可用目标由 YARP 的可用目标策略综合判断。

## 控制台和指标

“配置集群”页面的运行状态列显示目标是否已驱逐、驱逐原因和计划恢复时间。数据来自 `/api/lb/outliers`，该接口与其他控制台 API 使用相同认证。

- `lywaf_outlier_ejected`：目标当前是否处于驱逐期。
- `lywaf_outlier_recovery_timestamp_seconds`：计划恢复 Unix 时间。
- `lywaf_outlier_decisions_total`：按 `consecutive_connection_failures`、`consecutive_5xx`、`error_rate` 或 `limit_reached` 统计决策。

告警应同时观察驱逐计数、Cluster 可用实例数和请求错误率。单个实例偶发驱逐不一定代表整体服务不可用。
