# 多节点控制台

多节点控制台把 Controller 已配置的节点放在同一运维视图中，用于发现版本漂移、上游故障、安全事件集中爆发和配置分发异常。它不替代 Prometheus：控制台提供当前操作上下文，指标系统负责长期趋势和告警。

## 启用条件

控制端必须启用 `Distribution` 并设置 `Role = "Controller"`。目标节点设置 `Role = "Node"`，双方使用相同 HMAC 密钥；生产环境还应使用 HTTPS 并限制控制端口来源。完整配置见 [多节点配置分发](35-多节点配置分发.md)。

登录控制台后，从“配置管理 -> 节点管理”进入页面。页面每 15 秒自动刷新，也可手动立即刷新。

## 节点状态

节点列表显示程序版本、当前配置版本、运行状态、进程运行时长、分布式状态条目数和最后在线时间。Controller 并行请求 `/api/v1/distribution/agent/dashboard`；该机器接口只接受 HMAC，不接受控制台 JWT。

请求失败时，节点标记为离线。若该节点曾成功返回，页面保留最后一次快照并标记“离线（缓存）”，便于网络分区期间判断最后已知版本；缓存数据不会计入当前在线安全汇总。

## 时钟偏差

Controller 以请求发送和响应接收时间的中点估算节点时钟偏差，减少网络往返延迟的影响。绝对偏差超过 `AllowedClockSkewSeconds` 时显示警告。偏差过大还会使 agent HMAC 请求被拒绝，应先校准 NTP，再排查密钥和网络。

## 上游健康

“上游健康”展示每个节点当前 YARP Cluster 和 Destination，包括地址、主动健康、被动健康及并发请求数。状态来自节点内存中的权威 YARP 对象，不会经本机 HTTP 再绕行一次。

同一上游在不同节点上分别显示，因为 DNS、网络和被动失败统计可能不同。节点离线时不把缓存健康状态当作当前状态。

## 安全事件聚合

节点返回最近 24 小时最多 100 条聚合拦截事件及安全计数。Controller 按稳定 `EventId` 去重，重复轮询或重复交付不会生成重复行；同一事件有多个版本时保留 `LastHitAt` 最新的一条。页面最多展示最近 200 条。

顶部“攻击来源”是在线节点各自去重计数之和，不是跨节点全局精确去重值。需要精确全局来源数时，应从 DuckDB 或集中日志按 IP 聚合。

## 操作权限

权限按控制台登录用户名匹配，比较时不区分大小写：

```ly
Permissions {
    GlobalOperators = ["admin"]
    NodeOperators {
        edge-01 = ["east-operator"]
    }
}
```

- 全局操作员可以选择全部节点、操作任何节点并控制所有分发任务。
- 节点操作员只能选择获授权节点；涉及多个节点的任务要求对每个目标都拥有权限。
- 未授权用户仍可查看控制台，但操作按钮为只读。
- 两张权限表都为空时，为兼容旧配置，所有已登录用户拥有全局权限。

暂停、继续和回滚会重新在服务端校验任务涉及的全部节点，不能通过直接调用 API 绕过页面限制。权限配置变更后应重新加载配置并用只读账号验证。

## 网络分区与排障

1. 查看节点是否显示“离线（缓存）”，并核对最后在线时间。
2. 从 Controller 测试目标 `Endpoint` 的 TLS 和连通性。
3. 对比双方 `SharedSecret`、系统时间和 `AllowedClockSkewSeconds`。
4. 查看节点日志中的 HMAC 拒绝、配置加载和 YARP 健康检查记录。
5. 网络恢复后手动刷新；缓存会被新快照替换，安全事件按事件 ID 去重。

不要在网络分区期间仅凭缓存状态继续大范围分发。先恢复节点可达性，再通过灰度批次提交配置。
