# 请求镜像与影子流量

请求镜像把命中的入口请求异步复制到影子环境，用于新版本验证、兼容性观察和只读审计。镜像不是负载均衡：主请求仍只由原 Cluster 处理，镜像响应的状态、正文、超时和异常都不会改变客户端结果。

## 配置

进程级后台资源限制：

```ly
RequestMirroring {
    QueueCapacity = 256
    Workers = 2
    TimeoutSeconds = 10
}
```

在站点或具体路径中配置策略：

```ly
example.com {
    /api/* {
        Mirror {
            Target = "https://shadow.internal"
            Percentage = 10
            Methods = ["GET", "HEAD"]
            MaxBodyBytes = 1048576
            AllowedHeaders = ["Accept", "Content-Type", "User-Agent"]
        }
        reverse_proxy http://production.internal
    }
}
```

`Target` 是镜像端的 origin；原始 Path 和 Query 会附加到该 origin。`Percentage` 限制为 `0..100`。站点级策略会被路径继承，路径内再次配置 `Mirror` 可覆盖它。

## 可重放边界

默认只允许 `GET`、`HEAD`、`OPTIONS`。`POST`、`PUT`、`PATCH` 可能产生订单、扣款或写库等副作用，只有确认镜像端完全隔离后才能显式加入 `Methods`。镜像请求携带 `X-LyWaf-Mirror: true`；再次进入 LyWaf 时不会继续镜像，避免回环。

请求正文只有在存在可信 `Content-Length` 且不超过 `MaxBodyBytes` 时才会复制。未知长度的流式正文和超过上限的正文直接跳过，主请求不受影响。读取后的入口流会复位，后续 WAF 与代理仍读取原始内容。

默认只复制 `Accept`、`Content-Type`、`User-Agent`，不会复制 `Authorization`、Cookie、客户端 IP 或代理身份头。确有需要时可在 `AllowedHeaders` 显式增加 Header，但应先评估凭据泄露和影子端权限。

## 背压与失败隔离

镜像使用固定 worker 数量和有界 Channel。入口线程仅调用 `TryWrite`：队列满时立即跳过，不等待镜像端释放容量。每个请求受 `TimeoutSeconds` 约束，worker 只读取响应头并立即释放响应，不把镜像正文保存在内存。

`lywaf_mirror_requests_total{outcome=...}` 同时通过 Prometheus/OpenMetrics 和 OTLP 记录：

- `queued`：成功进入后台队列。
- `queue_full`：队列已满或停止，镜像被跳过。
- `success`：镜像端返回 2xx。
- `failure_status`：镜像端返回非 2xx。
- `timeout`：超过镜像超时。
- `failure`：网络或协议异常。

镜像失败只用于监控和告警，不应触发主请求重试、熔断或异常实例驱逐。

镜像中间件位于访问控制、WAF、CC、验证码和限速之后，因此被安全策略拦截的请求不会送往影子端。响应缓存命中、静态响应、文件服务和 WebSocket 升级也不镜像；该功能只观察通过检查并进入普通 HTTP 回源分支的流量。
